# 标签树允许显式拖入形成会话级父关系

标签树继续以 Chrome `openerTabId` 作为自动父子关系的事实基础。用户在侧边栏拖放时，边缘定位线表示被拖子树根成为参考标签的同级，中间整行高亮表示被拖子树根成为参考标签的直接子节点。扩展只为被拖节点或子树根节点记录一条当前浏览器会话有效的 `tabId -> parentTabId` 覆盖，后代关系保持不变。该覆盖只表达用户的显式拖放意图，不尝试修改 Chrome 不可写的 `openerTabId`，也不推测其他标签之间的关系。具体交互与深度约束见 `docs/superpowers/specs/2026-08-09-tab-tree-depth-drag-collapse-design.md`。

## 约束

- 拖放意图统一表示为 `reference + relation`：`reference` 是参考标签，`relation` 只取同级或直接子级，不再由横向坐标或手动深度字段决定父级。
- 边缘定位线使根标签、子标签或父节点成为参考标签的同级；中间整行高亮使其成为参考标签的直接子节点。拖动父节点时只改写子树根节点的父关系，后代保持相对层级与顺序，放置后最大深度不得超过四级。
- `after` 同级关系和直接子级关系都按参考标签完整子树的末尾计算真实排序位置；直接子级关系建立后，拖动子树根成为参考标签最后一个直接子节点。
- 覆盖关系不得跨越窗口、固定标签区域或 Chrome 原生标签组边界，也不得把标签挂到自己的子树中。
- 手动父关系与折叠、拖出状态一样按窗口保存在 `storage.session`，浏览器会话结束后不保留。
- 标签被拖出原树时删除手动父关系；父标签关闭时，其手动子标签提升为根标签。
- 标签 ID 被 Chrome 替换时，同时迁移覆盖关系的子节点和父节点 ID。
- 树构建仍保持 O(n)，无轮询、无远程状态和跨会话长期关系库。

## 结果

该补充保留 Chrome 打开来源作为默认事实，同时支持用户明确把已有标签整理进标签树。会话级覆盖提供可撤销的人工修正，不会永久维护一套脱离 Chrome 的标签关系。
