# 标签性能、一致性、快捷图标缓存与历史记录去重设计

## 背景

SideTab Lite 0.7.0 已使用 Chrome 标签与分组事件维护当前窗口的侧栏视图，并通过启动快照、事件缓冲和失败重同步处理大部分异步竞争。但当前实现仍有四个问题：

1. 未订阅 `chrome.tabs.onReplaced`。Chrome 因预渲染或 Instant 替换标签时，旧标签 ID 可能残留，新标签可能缺失或重复，形成“幽灵标签页”。
2. 标签创建、关闭、移动、固定或分组结构变化时会重新创建整个列表 DOM。标签数量达到数百时，节点创建、替换和 favicon 加载会产生可感知卡顿。
3. 历史记录搜索在过滤无效记录或去重前限制为 20 条，无法在候选结果重复时补足 20 条唯一结果。
4. 快捷网站图标只依赖当前打开标签的 favicon 和网站根目录图标，侧栏关闭后不会保留已验证可用的图标地址。

本次优化面向最多 500 个同时打开的标签，优先保证标签状态真实、结构变化顺滑和内存稳定，不引入虚拟列表。

## 目标

- 订阅并正确处理 `chrome.tabs.onReplaced`，确保侧栏不存在已被 Chrome 替换的旧标签。
- 启动、重同步与实时事件交错时，最终视图始终与当前窗口 Chrome 状态一致。
- 标签与分组结构变化时按 ID 复用现有 DOM 节点，只创建、删除或移动必要节点。
- 避免未变化 favicon 的重复赋值、图片加载和历史结果 DOM 重建。
- 历史记录按规范化后的完整 URL 去重；候选足够时返回 20 条唯一有效记录。
- 持久化快捷网站最后成功加载的图标地址，侧栏重开后直接复用。
- 标签页、历史记录和快捷网站统一使用本地网络图标兜底，不再根据标题生成首字符图标。
- 将扩展版本从 `0.7.0` 升级到 `0.8.0`，并生成对应发布包。

## 非目标

- 不实现虚拟列表、无限滚动或分页标签列表。
- 不改变标签、分组、拖拽、右键菜单、中键关闭和快捷网站的交互规则。
- 不改变历史搜索结果的标题、排序、键盘操作和向上展开方式。
- 不主动下载远程图标、不持久化任意网站图标，也不实现通用图片文件缓存。
- 不把本地网络兜底图标写入快捷网站图标缓存。
- 不增加轮询、常驻后台任务、content script 或新的 Chrome 权限。
- 不保证历史记录不足 20 条唯一网页时仍返回 20 条。

## 总体方案

保留现有 `TabStore`、`TabGroupStore`、联合列表模型和事件缓冲状态机。优化集中在三个边界：

1. 标签事件层新增替换事件，并把异步读取的新标签纳入有序缓冲。
2. 渲染层从“创建完整 Fragment 后 `replaceChildren`”改为按键协调现有节点。
3. favicon 与历史搜索层增加稳定签名、快捷网站图标地址缓存和完整 URL 去重。

不引入虚拟列表的原因是 500 个紧凑标签行的 DOM 数量仍可控，而虚拟化会显著增加分组折叠、拖拽落点、键盘导航和滚动位置恢复的复杂度。

## 标签替换事件

### 事件接口

`TabEventHandlers` 新增替换处理器，接收完整的新标签和被替换的旧标签 ID。`subscribeToTabEvents` 订阅 `tabs.onReplaced(addedTabId, removedTabId)`，并通过 `tabs.get(addedTabId)` 获取完整标签。

读取成功后再次检查新标签的 `windowId`：

- 新标签属于当前窗口时，转发替换事件。
- 新标签属于其他窗口时忽略。
- 查询失败、标签消失或数据无效时，请求一次当前窗口完整重同步。

订阅销毁后，延迟返回的查询结果不得再进入状态层。

### 有序缓冲

替换事件与跨窗口附加事件一样包含异步 `tabs.get`。二者共用有序异步事件槽：事件到达时立即在缓冲队列中占位，查询完成后再把具体状态变更填入该位置。这样后到达的关闭、移动或更新事件不会越过尚未完成的替换查询。

启动查询或重同步期间发生替换时：

1. 快照查询与事件订阅保持并行。
2. 替换事件按接收顺序进入缓冲队列。
3. 快照应用后依次执行替换及其后的事件。
4. 最后只渲染一次联合列表并同步一次 favicon。

实时替换使用一个原子状态变更：删除 `removedTabId`，再添加完整的新标签。旧 ID 不得继续存在，新 ID 最多存在一次。

### 失败恢复

替换查询失败时调用现有合并重同步机制。多个并发失败只共享一次查询；重同步失败时保留最后一个一致视图，不循环重试。页面销毁时释放所有未完成事件槽，延迟结果不得恢复 UI 或引用已销毁控制器。

## 增量 DOM 协调

### 节点身份

`tab-renderer.ts` 继续维护标签 ID 到行节点、分组 ID 到标题节点的映射。每次接收新的联合列表时生成目标键序列：

- 标签键：`tab:<tabId>`
- 分组键：`group:<groupId>`

同一 ID 的节点必须保持对象身份。只有新键创建节点，消失键删除节点；顺序变化通过 `insertBefore` 或 `append` 移动现有节点。

### 协调流程

1. 验证输入中不存在重复标签 ID、重复分组 ID 或键冲突。
2. 为新条目创建缺失节点，但暂不删除当前 DOM。
3. 按目标顺序逐个放置节点；位置正确的节点不执行 DOM 移动。
4. 删除不在目标键集合中的旧节点，并同步清理索引。
5. 对目标条目执行属性补丁，更新标题、激活、固定、分组和拖拽状态。
6. 根据目标条目数量更新空状态。

输入验证或节点创建失败时保留原 DOM 和索引，避免部分列表替换造成状态撕裂。

### favicon 复用

标签行复用时保留已有 `<img>`。只有 `favIconUrl` 或页面 URL 产生的候选列表变化时才重建 favicon 节点；标题变化不影响兜底图标。移动、固定、激活和分组变化不得重新设置未变化图片的 `src`。

## 状态更新性能

普通 `tabs.onUpdated` 保持就地 `patchTab`。只有标签的 `index`、`pinned`、`groupId` 或可见性发生结构变化时才运行联合列表协调。

当前标签到 favicon 的 origin 映射生成稳定签名。签名与上一次相同时，不调用快捷网站和历史搜索控制器的 `setFaviconsByOrigin`。历史结果框打开时也不会因标题、加载状态或激活状态等无关标签更新而重新创建最多 20 个结果节点。

不使用 `setInterval`、轮询或为每个标签注册独立监听器。所有标签交互继续使用列表事件委托。

## 快捷网站图标缓存

### 存储结构

新增独立的 `shortcutFaviconCacheV1` 存储项，以快捷网站的 HTTP origin 为键，以最后成功加载的安全图标地址为值。缓存不与快捷网站编辑数据混合，读取失败时按空缓存处理，不阻止侧栏和设置对话框启动。

缓存只保留当前快捷网站对应的条目。快捷网站删除、修改域名或恢复默认设置后，下一次保存会清理不再使用的 origin，条目数量不得超过快捷网站上限 12。

允许保存：

- 规范化后的 `http:` 或 `https:` 图标 URL。
- Chrome 提供的 `data:image/*` favicon，但单条序列化长度不得超过 32 KiB。

其他协议、无效 URL、空值和超限 Data URL 不进入缓存。继续依赖现有 `storage` 权限，不新增主机权限或远程请求能力。

### 候选优先级

快捷网站图标候选按以下顺序去重：

1. 当前已打开标签提供的最新 `favIconUrl`。
2. `shortcutFaviconCacheV1` 中该 origin 最后成功加载的地址。
3. 网站根目录 `/favicon.ico`。
4. 本地 `assets/icons/network.svg` 网络兜底图标。

当前标签 favicon 与缓存地址相同时只尝试一次。图标候选变化前保留现有 `<img>`，避免快捷入口重绘或重复设置相同 `src`。

### 写入与淘汰

只有前三类远程或 Data URL 候选触发 `load` 后，才把该候选记录为成功地址。本地网络兜底图标不参与加载回调和缓存。缓存值未变化时不调用 `storage.local.set`。多个 origin 在同一轮加载中更新时合并为一次异步写入，并由单一写入队列串行提交，避免旧写入覆盖新状态。

缓存候选触发 `error` 时立即从内存状态删除并继续下一个候选；持久化删除进入同一合并写入队列。根目录候选失败时不记录永久失败状态，以便网站未来新增 favicon 后可以再次加载。

缓存不设置固定过期时间。已打开标签提供新 favicon 时，只有新地址成功加载后才覆盖旧缓存；失败时继续保留或回退到仍可用的旧候选。

页面销毁后清除待执行的合并任务并使写入代次失效。已经开始的 Chrome 存储 Promise 可以自然结束，但不得再次更新组件状态、重新排队或持有 DOM 节点。

## 统一网络兜底图标

用户提供的 `C:\Users\NUC\Downloads\网络.svg` 清理后保存为 `assets/icons/network.svg`。发布资源只保留以下安全结构：

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1024 1024">
  <path d="..." />
</svg>
```

必须删除 XML 声明、DOCTYPE、`t`、`class`、`version`、`p-id`、`xmlns:xlink`、`width`、`height` 和其他生成器属性。资源不得包含脚本、事件属性、远程引用、额外元素或外部命名空间。

标签页、历史记录和快捷网站不再根据标题生成首字符。所有 favicon 候选耗尽或没有候选时，渲染一个无文本的兜底 `<span>`，通过 CSS `mask-image: url("../assets/icons/network.svg")` 显示本地图标并继承 `currentColor`：

- 标签页：16px × 16px。
- 历史记录：16px × 16px。
- 快捷网站：20px × 20px。

兜底元素不是 `<img>`，不发起远程请求，不触发快捷图标 `load`/`error` 委托，也不进入 `shortcutFaviconCacheV1`。favicon 候选重新变为可用时，可以用真实图片替换兜底元素。

## 历史记录完整 URL 去重

### 查询与筛选

空搜索和关键词搜索均调用：

```text
chrome.history.search({ text, startTime: 0, maxResults: 200 })
```

候选结果按 Chrome 返回顺序处理：

1. 跳过缺少 URL 的记录。
2. 使用 `new URL(rawUrl)` 解析地址。
3. 只保留 `http:` 和 `https:`。
4. 使用 `url.href` 作为展示 URL 和去重键。
5. 已出现的完整 URL 直接跳过，保留第一次出现的最近记录。
6. 收集到 20 条唯一有效记录后立即停止。

路径、查询参数或锚点不同的 URL 视为不同页面。同一完整 URL 即使标题不同也只保留最近一条。若 200 条候选中不足 20 条唯一有效记录，则返回实际数量。

### 内存边界

单次历史查询最多处理 200 条候选，去重集合最多保存 200 个字符串，最终结果最多保存 20 条。新的查询通过现有 generation 机制淘汰旧响应，组件销毁后延迟响应不得更新 DOM。

## 性能验收

自动化测试使用确定性行为作为主要门槛：

- 500 个标签重新排序后，未新增或删除的标签行保持原对象身份。
- 新增一个标签只创建一个标签行；删除一个标签不重建其他行。
- 重复渲染不调用 `replaceChildren`，不重新设置未变化 favicon 的 `src`。
- 连续 500 次结构变化后，渲染器索引数量、DOM 节点数量和目标模型一致。
- 销毁后索引清空、委托监听器移除，反复结构变化不产生线性堆增长。

提供合成基准测试记录 100、500 个标签的结构更新耗时。500 个标签单次结构调整的中位耗时目标低于 50ms，但该时间值受机器与 DOM 实现影响，只作为人工性能回归依据，不作为 CI 的硬失败条件。

## 一致性验收

- `onReplaced` 后旧 ID 完全消失，新 ID 只出现一次。
- 其他窗口的替换事件不改变当前窗口列表。
- 替换查询失败只触发一次合并重同步。
- 替换、关闭、更新和移动事件按接收顺序生效。
- 启动快照比替换事件旧时，事件回放覆盖旧快照。
- 重同步回放期间再次收到替换事件时，后续重同步请求不会丢失。
- 页面清理后所有八类标签事件监听器均注销，未完成查询不能恢复标签。

## 历史搜索验收

- 前 20 条候选包含重复 URL 时，继续读取后续候选并补足 20 条。
- 同一完整 URL 使用最近记录的标题，只出现一次。
- 不同路径、查询参数和锚点分别保留。
- 非网页协议、无效 URL 和重复 URL 不占用结果名额。
- 不足 20 条唯一记录时返回实际数量。
- 搜索失败、旧响应淘汰、销毁清理和键盘操作保持现有行为。
- 历史记录没有可用 favicon 时展示本地网络图标，不再显示标题首字符。

## 快捷网站图标缓存验收

- 当前标签 favicon、缓存地址和根目录图标按既定优先级尝试且自动去重。
- 只有成功触发 `load` 的安全候选进入缓存，加载失败的缓存候选被淘汰。
- 本地网络兜底图标永不进入缓存，也不触发缓存回调。
- 相同地址重复加载不产生额外存储写入。
- 多个图标连续成功时合并写入，串行队列不会让旧快照覆盖新缓存。
- 快捷网站删除、改域名和恢复默认设置后只保留当前最多 12 个 origin。
- 无效协议和超过 32 KiB 的 Data URL 不写入缓存。
- 缓存读取或写入失败不影响快捷网站打开、编辑和其他侧栏功能。
- 页面销毁后延迟图片事件和存储结果不更新状态或重新排队。

## 网络兜底资源验收

- `network.svg` 通过与搜索、设置图标相同级别的结构白名单检查。
- 标签页、历史记录和快捷网站的真实 favicon 候选耗尽后均展示网络图标。
- 三处 DOM 不再包含由标题生成的首字符兜底文本。
- CSS mask 在 16px 和 20px 尺寸下继承当前文字颜色，不改变行高和按钮尺寸。
- `network.svg` 进入 dist 和 ZIP 白名单，发布包文件总数从 13 个变为 14 个。

## 发布

扩展版本从 `0.7.0` 升级为 `0.8.0`。实现完成后更新 `package.json`、`package-lock.json`、`manifest.json` 和项目根目录 `update.log`，记录本次一致性、性能、快捷网站图标缓存和历史搜索变化。

发布前运行完整类型检查、全部测试、构建和发布目录审计，生成：

```text
release/sidetab-lite-0.8.0.zip
```

ZIP 文件集合在现有发布白名单中新增 `assets/icons/network.svg`，总数为 14 个；权限和内容安全策略保持不变，不新增权限或远程代码。
