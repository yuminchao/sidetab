# 搜索来源标签、连续分组容器与分组拖动设计

## 背景

SideTab Lite 当前已支持收藏夹与历史记录混合搜索、Chrome 标签组展示、单标签拖动和标签组右键管理。本次改动需要提升来源辨识度和标签组整体感，并允许用户直接拖动整个标签组调整位置，同时继续保持性能优先、事件驱动同步和低内存开销。

## 目标

1. 搜索结果右侧显示来源胶囊，明确区分收藏夹和历史记录。
2. 分组标题与组内标签形成一个连续的同色圆角容器。
3. 支持拖动分组标题，将整个分组及其成员作为一个整体上下移动。
4. 不新增权限、Chrome 查询、轮询、长期成员缓存或额外 DOM 包裹层。

## 非目标

- 不支持把一个分组拖入另一个分组或自动合并分组。
- 不改变现有单标签拖动、标签组右键菜单或搜索结果排序与去重规则。
- 不改变组内成员顺序、分组 ID、标题、颜色或折叠状态。
- 不在普通网页预览中模拟完整 Chrome 扩展 API。

## 一、搜索结果来源胶囊

### 数据与渲染

继续使用现有 `SearchResult.source`，值仅为 `bookmark` 或 `history`。`history-search` 创建结果行时，在 favicon 和标题后追加来源元素：

- `bookmark` 显示“收藏夹”。
- `history` 显示“历史记录”。

空查询仍只请求最近历史记录，因此空查询结果全部显示“历史记录”。本功能不得新增收藏夹或历史记录查询，也不得改变合并、去重和数量上限。

### 样式

结果行使用三列布局：`16px 图标 + minmax(0, 1fr) 标题 + auto 来源胶囊`。

- 胶囊高度约 `18px`，字号 `11px`，左右内边距 `6px`，完整圆角。
- 收藏夹使用浅蓝背景和蓝色文字。
- 历史记录使用浅灰背景和灰色文字。
- 标题继续单行省略；在 180px 最小宽度下优先压缩标题，来源文字必须完整可见。
- 胶囊不参与点击命令，不新增独立焦点或事件监听器。

## 二、连续分组容器

### 列表模型

列表继续使用扁平 DOM，不增加分组包装元素。构建可见列表时，为每个组内 Tab 计算并携带以下渲染信息：

- `groupId`
- `groupColor`
- 组内可见位置：`first`、`middle`、`last` 或 `single`

折叠分组不渲染成员 Tab。展开分组的位置标记基于当前完整、有序的组内可见成员计算。成员增删、跨组移动、标签替换、分组折叠或分组删除后，下一次现有列表重建必须刷新位置标记。

### 增量渲染

`tab-renderer` 把分组 ID、颜色和位置写入已有 `.tab-row` 的 dataset。普通未分组和固定 Tab 必须移除这些分组 dataset，防止节点复用时残留旧边框状态。

现有 keyed DOM 复用保持不变：更新位置、颜色或分组归属时只 patch 现有行，不重建 favicon、标题、关闭按钮或整行节点。

### 视觉规则

- 分组标题行保持 `20px` 高度，圆角半径为 `8px`。
- 展开时标题仅保留顶部圆角，底部与成员边框连续衔接。
- 折叠时标题四角都为 `8px` 圆角。
- 组内 Tab 使用 `2px` 同色左右边框。
- 最后一个或唯一成员增加同色底边和底部 `8px` 圆角。
- 首个成员直接衔接标题，不增加单独顶边；中间成员不增加横向分割线。
- hover、active、右键临时选中和拖动反馈不得覆盖同色边框，不得改变现有行高。

标题前景使用自动对比色：深色分组背景使用白字；黄色、紫色、橙色等浅色背景使用 `#202124`。深色主题沿用当前浅色分组背景变体并使用深色文字。强制色模式使用系统颜色保留边界和焦点可见性。

## 三、分组整体拖动

### 交互语义

分组标题行成为拖动源。拖动分组时，整个分组及全部成员作为一个块移动：

- 拖到另一分组上半区时，放到目标分组之前。
- 拖到另一分组下半区时，放到目标分组之后。
- 拖到未分组 Tab 上半区或下半区时，放到该 Tab 之前或之后。
- 拖到目标分组的任一成员时，按整个目标分组块计算 before/after，不允许嵌套或合并。
- 固定标签区域不是合法目标；分组不得移动到固定标签之前或固定标签集合内部。
- 拖到自身分组、源分组成员或计算后位置未变化时静默取消。
- 展开和折叠分组均可整体拖动。

现有单标签拖动语义保持不变。拖动控制器应使用有判别字段的 source 类型区分单标签和分组，避免两个分支共享含义不明确的数字 ID。

### 重排模型

新增纯函数分组重排计划，输入为最新标签快照、最新分组快照、源 `groupId` 和目标描述。计划必须：

1. 校验源分组和成员仍存在且位于同一窗口。
2. 把目标解析为完整列表块的前后边界。
3. 拒绝固定区、其他窗口、源分组内部和无变化目标。
4. 返回 `groupId`、目标 `index` 和 `windowId`，不保存成员数组到长期状态。

执行前由 Sidebar 再次从 `TabStore` 和 `GroupStore` 读取最新快照并重新计算计划，防止菜单、拖动开始或 DOM 状态陈旧。

### Chrome API 与同步

有效计划只调用一次：

```ts
chrome.tabGroups.move(groupId, { index, windowId })
```

成功后不直接修改 Store 或 DOM，等待 Chrome 标签和分组事件驱动现有同步流程。失败时显示稳定中文错误，并只请求一次现有合并重同步。

### 并发与生命周期

- 同一分组正在执行折叠、右键管理或拖动时，不允许再次提交分组操作。
- 不同分组保持独立，不使用全局拖动锁阻塞无关命令。
- 拖动开始后只保存 source 判别信息、目标判别信息和 DOM 反馈引用。
- 滚动、resize、搜索状态变化、源或目标移除、dragend、drop、失败和 destroy 都必须清理反馈。
- cleanup 后迟到的成功或失败不得更新状态消息、DOM 或重新触发同步。

### 拖动反馈

- 分组拖动源整体轻微透明，标题行和可见成员共同体现拖动状态。
- 合法目标显示不改变布局的横向位置线。
- 不创建拖动预览克隆、不缓存成员 DOM 集合、不修改行高。

## 四、性能与内存约束

- 搜索来源胶囊只增加一个静态 span，不增加监听器。
- 分组边界状态在现有列表构建或渲染遍历内完成，总复杂度保持 O(n)。
- 不得为每次 render 对每个 Tab 反复扫描完整标签数组。
- 不新增长期 `groupId -> tabIds` 缓存；执行拖动时从内存 Store 快照临时计算。
- 一次分组移动只调用一次 `chrome.tabGroups.move()`，不逐个调用 `chrome.tabs.move()`。
- 不新增 `chrome.tabs.query()`、`chrome.tabGroups.query()`、`setInterval()` 或长期 `setTimeout()`。

## 五、错误与边界处理

- 来源未知时不得生成空胶囊；类型层应保证仅有两个合法来源。
- 分组颜色或位置 dataset 在 Tab 离开分组后必须清理。
- 源分组、目标分组或目标 Tab 在 drop 前消失时静默取消。
- Chrome API 失败后保留真实浏览器状态，依赖一次重同步恢复视图。
- 无成员分组、跨窗口目标、固定目标和无变化计划不得调用 API。
- 折叠分组的成员索引必须来自 Store，不依赖当前不可见 DOM。

## 六、测试与验收

### 自动化测试

1. 搜索控制器：验证收藏夹和历史记录文字、来源 class、DOM 顺序、点击行为不变、空查询仅历史记录。
2. CSS：验证三列布局、两种胶囊配色、固定尺寸、180px 无正最小宽度和无横向溢出规则。
3. 列表模型：验证首/中/末/单成员、折叠组、成员增删、跨组移动和颜色映射。
4. 渲染器：验证 dataset 写入与清理、节点复用、普通 Tab 不带分组状态。
5. 拖动控制器：验证标签/分组 source 区分、目标 before/after、固定区拒绝、自身取消和全部清理路径。
6. 分组重排模型：验证组前后移动、未分组目标、折叠组、跨窗口、固定区、无变化和 500 标签线性边界。
7. 动作与 Sidebar 集成：验证一次 `tabGroups.move()`、执行瞬间重算、事件驱动成功、失败单次重同步、忙碌互斥、销毁后迟到结果无副作用。

### 最终验收

- 运行完整类型检查、Vitest、构建和 dist 审计。
- 运行 100/500 标签渲染基准，确认节点数和耗时保持线性。
- 审计权限、查询、轮询、定时器和监听器数量无非必要增长。
- 在 180px、240px 和常规宽度检查来源胶囊、标题省略和连续分组边框。
- 在真实 Chrome 扩展环境验证展开/折叠分组整体拖动、失败恢复和事件顺序。
- 打包时递增版本号，并在 `update.log` 顶部记录本次功能、性能边界与未新增权限。

## 七、验收标准

1. 用户可从搜索结果右侧立即区分收藏夹和历史记录。
2. 展开分组呈现为一个连续同色圆角容器，折叠标题为完整圆角条。
3. 拖动分组标题可整体移动全部成员，且不会改变成员关系或组内顺序。
4. 单次有效移动只调用一次 `chrome.tabGroups.move()`。
5. 所有成功状态由 Chrome 事件同步，失败只触发一次合并重同步。
6. 全量测试、性能基准、dist 审计和窄宽度视觉检查通过。
