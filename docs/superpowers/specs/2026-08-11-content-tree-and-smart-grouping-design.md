# 内容树开关与智能分组设计

## 目标

本次改动包含三个互相关联的用户入口：

1. 把设置中的“新 Tab 行为”改为默认关闭的“内容树”开关。
2. 把“快速分组”改名为“同网站快速分组”，并优先复用已经包含同类标签的 Chrome 分组。
3. 在标签右键菜单增加“一键分组”，按当前窗口的标签分类批量形成分组。

设计要求保持当前侧边栏的性能和状态一致性：使用内存快照规划，不增加权限、轮询、长期缓存或后台任务；Chrome API 部分成功或失败后，以 Chrome 真实状态为准重新同步。

## 术语

- **分类**：一个标签用于自动分组的稳定键和展示名称。
- **匹配分组**：实际成员中至少包含一个目标分类标签的现有 Chrome 分组。
- **普通网站单例分类**：当前窗口的全部未固定标签中，只出现一次的 HTTP/HTTPS hostname；一键分组只处理其中尚未分组的标签。
- **候选标签**：当前窗口中未固定、协议受支持，并符合当前命令范围的标签。
- **内容树**：现有基于 opener 和会话级父关系覆盖构建的父子标签展示。

## 内容树设置

### 界面

- 设置区标题改为“内容树”。
- 使用一个二元开关，不再显示“无父节点 / 作为当前 Tab 子节点”单选项。
- 开启时，新标签自动成为当前活动标签的子节点，并启用现有树形展示、折叠和树拖放。
- 关闭时使用平铺标签展示，并沿用现有逻辑清除当前窗口会话中的折叠、脱离和手动父关系，避免重新开启后恢复旧结构。

### 配置与迁移

新配置字段为：

```ts
contentTreeEnabled: boolean
```

读取优先级和迁移规则：

1. 存在合法 `contentTreeEnabled` 时直接使用。
2. 否则，旧字段 `newTabBehavior: "child"` 迁移为 `true`。
3. 旧字段 `newTabBehavior: "root"` 迁移为 `false`。
4. 两个字段都不存在或旧字段非法时默认 `false`。
5. 保存设置时只写 `contentTreeEnabled`，不再写 `newTabBehavior`。

因此，新安装默认关闭；已经显式保存子标签模式的用户升级后保持开启，显式保存根标签模式的用户保持关闭。

## 标签分类器

分类器是同网站快速分组和一键分组共用的纯模型。固定标签和未列出的协议不返回分类。

| URL | 分类键 | 新建组名 |
| --- | --- | --- |
| `http://`、`https://` | `site:<完整 hostname>` | 完整 hostname |
| `file://` | `special:file` | 本地文件 |
| `chrome://settings/*` | `special:chrome-settings` | Chrome 设置 |
| 其他 `chrome://*` | `special:chrome` | Chrome 页面 |

HTTP/HTTPS 不去掉 `www`，不按可注册主域合并。分类只依赖 URL，不依赖标签标题或用户可修改的分组标题。

## 匹配现有分组

规划器一次扫描当前窗口标签，建立：

- 分类到全部非固定标签的映射；
- 分组到实际成员分类计数的映射；
- 分组在标签列表中的最早成员位置；
- 当前窗口已经使用的分组颜色。

一个分组只要实际成员包含目标分类，就属于匹配分组。多个分组匹配时：

1. 选择该分类成员数量最多的分组；
2. 数量相同时，选择最早成员位置更靠前的分组；
3. 不根据分组标题、颜色或分组 ID 猜测业务含义。

“其他”属于合成分类，不能通过成员的单一分类或标题可靠识别。扩展创建“其他”分组后，把分组 ID 按窗口保存到 `storage.session` 的智能分组角色状态；再次执行一键分组时，只有该 ID 仍指向当前窗口中存在的分组才复用。分组删除、窗口变化、ID 失效或会话结束后清理该角色，不把用户自行命名为“其他”的分组当作系统分组。

## 同网站快速分组

“同网站快速分组”以右键标签的分类为唯一目标：

1. 右键标签固定、协议不受支持、分组快照未就绪或相关标签正在执行分组操作时，命令禁用。
2. 执行瞬间从最新窗口快照重新计算分类、候选和匹配分组。
3. 候选包含该分类的全部非固定标签，包括未分组标签和位于其他 Chrome 分组中的同类标签。
4. 存在匹配分组时，把尚未位于目标分组的候选加入选中的匹配分组，不重命名、不改颜色；已经在目标分组中的成员不重复提交给 Chrome API。
5. 不存在匹配分组时，即使只有一个候选，也创建以分类展示名命名的新组。
6. 从其他分组移出的同类标签可能使原分组变空；该结果由 Chrome 原生分组行为处理。
7. 新建组颜色优先使用当前窗口未占用颜色，九色都占用后按现有稳定规则循环复用。

## 一键分组

“一键分组”位于标签右键菜单的分组区域，但不依赖右键目标分类。它处理当前窗口所有未固定、未分组且协议受支持的标签；已有分组成员保持原位，只作为复用目标的成员证据。

### 规划顺序

1. 对每个分类查找匹配分组；存在时，将该分类的未分组候选加入匹配分组。
2. 没有匹配分组的普通 HTTP/HTTPS 分类：
   - 候选数量大于 1 时，新建 hostname 分组；
   - 候选数量等于 1 时，加入普通网站单例集合。
3. 普通网站单例候选集合加入 `storage.session` 中记录且仍有效的“其他”角色分组；没有有效角色分组时，新建名为“其他”的分组并记录其 ID。
4. `file://`、“Chrome 设置”和“Chrome 页面”始终分别处理；即使只有一个候选，也加入匹配分组或新建各自的独立分组，不进入“其他”。
5. 本次需要新建多个组时，每创建一个组都把选中颜色加入计划内占用集合，尽量避免本批次颜色重复。

没有任何可加入现有组或可形成新组的候选时，“一键分组”禁用。右键点哪个普通标签都不改变一键分组计划。

## 右键菜单

分组区域顺序固定为：

1. 添加到分组
2. 从分组中移除
3. 同网站快速分组
4. 一键分组

同网站快速分组和一键分组共用一个批量分组忙碌状态。任一命令执行期间，两项均禁用，避免重复提交。菜单继续支持鼠标、`Shift+F10`、方向键、`Enter`、空格和 `Esc`。

## 执行与失败恢复

分组计划只描述两类操作：

```ts
type SmartGroupOperation =
  | { kind: "reuse"; groupId: number; tabIds: number[] }
  | {
      kind: "create";
      title: string;
      color: TabGroupColor;
      tabIds: number[];
      role?: "other";
    };
```

- 复用组只调用 `chrome.tabs.group({ tabIds, groupId })`。
- 新建组调用一次 `chrome.tabs.group({ tabIds })`，成功后调用一次 `chrome.tabGroups.update()` 设置名称和颜色。
- 同网站快速分组只生成一个操作；一键分组按稳定分类顺序串行执行多个操作。
- 每个操作开始前使用最新内存快照确认标签仍在当前窗口、未固定，并满足该操作对分组状态的要求。
- 某一步失败后停止执行后续步骤，不尝试伪事务回滚；已经成功的 Chrome 分组结果保留。
- 失败后只请求一次合并的标签与分组重同步，并显示“部分分组失败”或当前同网站快速分组的明确错误。
- Chrome 事件负责正常成功路径的视图更新，控制器不提前伪造分组成员状态。
- “其他”角色只在新组成功创建并取得 Chrome group ID 后写入 `storage.session`；角色写入失败不回滚 Chrome 分组，但会报告部分失败并重新同步。分组移除事件和启动校验负责清理失效角色。

## 性能与模块边界

- 分类器只负责把单个标签映射为分类。
- 规划器只依赖标签和分组快照，输出不可变操作列表，不调用 Chrome API。
- 执行器只消费操作列表并调用 Chrome API，不重新实现分类规则。
- 单次规划复杂度为 O(n + g)，其中 n 是当前窗口标签数，g 是分组数及其成员关系。
- 不遍历浏览器其他窗口，不查询历史、收藏夹或网络，不新增缓存和监听器。

## 测试策略

### 设置

- 新安装和缺少新旧字段时默认关闭。
- 新字段优先于旧字段。
- 旧 `child`/`root` 分别迁移为开启/关闭。
- 保存后只存在 `contentTreeEnabled`。
- 开关控制新标签 opener、树展示和关闭时会话关系清理。

### 分类与规划

- HTTP/HTTPS 完整 hostname、file、Chrome 设置、其他 Chrome 页面分类正确。
- 固定标签和其他协议被排除。
- 多个匹配分组按同类成员数量和最早位置选择。
- 混合成员分组可以按实际同类成员参与匹配。
- “其他”只复用当前窗口 `storage.session` 中记录且仍有效的系统角色分组，不按标题误判用户分组。
- 一键分组覆盖网站多例、普通单例、三种特殊分类、匹配组复用和颜色去重。

### 菜单与集成

- 菜单顺序、禁用状态、键盘操作和忙碌门禁正确。
- 同网站快速分组可移动其他分组中的同类标签并复用目标组。
- 一键分组不移动已有分组成员，只处理未分组候选。
- 分组调用参数、执行顺序和标题颜色更新准确。
- 中途失败停止后续操作，只触发一次重同步并保留成功结果。
- 500 个标签下规划保持线性，不增加逐标签 Chrome API 查询。

## 不在本次范围

- 不按路径、页面标题、主域名或用户自定义规则分类。
- 不自动拆分、重命名或重新着色已有分组。
- 不对固定标签、`chrome-extension://`、`edge://` 或其他未列出协议分组。
- 不提供撤销一键分组或跨窗口分组。
- 本设计阶段不升级版本、不生成 ZIP。
