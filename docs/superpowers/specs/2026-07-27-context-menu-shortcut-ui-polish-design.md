# 右键快捷网站与界面细节优化设计

## 背景

当前标签右键菜单已经支持“复制标签页”和“固定标签/取消固定”，但菜单项缺少明确的悬停反馈，也不能把当前标签直接加入快捷网站。标签列表末尾的新建按钮目前是整行透明热区，不够像可点击控件；底部工具栏仍有顶部分割线，搜索框圆角也不够明显。

本次变更在不改变标签管理、拖动和快捷网站数据格式的前提下，完成以下优化：

- 右键菜单项增加悬停、键盘焦点和按下反馈。
- 标签列表末尾的加号改为带边框的紧凑按钮。
- 右键菜单增加“设为快捷网站”。
- 去掉底部搜索区域上方的分割线，将搜索框改为更明显的圆角外观。
- 将原有标签过滤输入框替换为历史记录搜索；聚焦时显示最近 20 条，输入后搜索全部历史记录，结果框向上展开。

发布版本从 `0.3.0` 升级为 `0.4.0`。

## 范围

### 包含

- 右键菜单视觉状态。
- 右键菜单命令、键盘导航和快捷网站持久化。
- 加号按钮、底部工具栏和搜索框样式。
- 历史记录查询、向上结果框、键盘操作和新标签打开。
- 相关单元测试、集成测试、视觉回归检查、商店验收清单和发布包。

### 不包含

- 不改变快捷网站设置对话框的编辑方式。
- 不改变快捷入口总开关；通过右键添加网站时保留当前开关状态。
- 不为快捷网站增加文件夹、分组、同步或导入导出。
- 除历史搜索所需的 `history` 权限外，不增加其他 Chrome 权限或网络请求 API。
- 不改变标签右键菜单为浏览器原生菜单。
- 不保留原有“搜索当前标签页”模式，也不增加搜索模式切换。
- 不预加载、持久化或上传浏览历史与搜索关键词。

## 方案选择

### 方案 A：复用现有快捷网站模型与存储层（采用）

右键菜单只分发标签 ID。侧边栏协调层读取当前标签与已保存的快捷网站设置，调用现有 URL 规范化、重复校验、12 项上限校验和存储逻辑，然后重新渲染快捷入口。

优点是职责清晰，错误文案和设置对话框保持一致，不会让菜单组件依赖 Chrome Storage。缺点是每次添加会发生一次本地存储读取和写入，但该操作只在用户点击菜单时发生，对常驻性能没有影响。

### 方案 B：让右键菜单直接持有快捷网站设置（不采用）

可以减少一次协调调用，但会把设置状态、校验和存储职责带进菜单组件，容易与设置对话框产生两个状态源。

### 方案 C：点击后打开设置对话框并预填网站（不采用）

可以让用户再次确认名称和地址，但比“设为快捷网站”的直接操作多一步，不符合快捷操作的目标。

### 历史搜索方案：独立控制器（采用）

新增独立 `history-search.ts`，把 Chrome History API、100ms 防抖、过期响应丢弃、结果渲染和键盘交互封装在一个边界中。`sidebar.ts` 只提供生命周期、当前标签 favicon 映射和新标签打开回调。

没有采用把全部逻辑继续写入 `sidebar.ts` 的方案，因为当前协调文件已经负责标签事件、右键菜单、拖动和快捷网站；继续内联会扩大回归范围。也不在启动时预加载完整历史记录，避免增加启动时间、内存占用和缓存一致性成本。

## 交互设计

### 右键菜单悬停状态

- 菜单项保持 28px 最小高度和现有紧凑间距。
- 鼠标悬停或键盘焦点落在可用菜单项时，使用 `CanvasText` 混合 8% 的中性色背景。
- 鼠标按下时背景提高到 13%。
- 禁用菜单项使用 `GrayText`，不显示悬停或按下背景。
- 保留现有 `focus-visible` 外轮廓，不能只依靠颜色表示键盘焦点。
- 浅色和深色主题均使用系统颜色，不引入固定单色主题。

### “设为快捷网站”菜单项

菜单顺序固定为：

1. `复制标签页`
2. `固定标签`或`取消固定`
3. `设为快捷网站`

鼠标右键和 `Shift+F10` 均可打开菜单。方向键在三个可用菜单项之间循环，`Enter` 和空格执行当前项，`Esc` 关闭并把焦点还给原标签行。

点击“设为快捷网站”后：

1. 菜单立即关闭。
2. 根据标签 ID 从当前窗口的 `TabStore` 重新取得标签，避免使用过期的标题或网址。
3. 只接受 `http:` 和 `https:` 地址。Chrome 内部页、扩展页、空地址或无效地址显示 `仅支持 HTTP 或 HTTPS 地址`。
4. 使用标签当前完整 URL 作为快捷地址，不自动缩短为站点根目录。
5. 使用去除首尾空白后的标签标题作为名称；标题为空时使用 URL 的主机名。
6. 新条目图标类型使用 `letter`。实际显示仍按现有规则优先采用同源标签的 `favIconUrl`，其次使用站点 `/favicon.ico`，最后显示名称首字符。
7. ID 使用 `crypto.randomUUID()` 生成，避免与现有条目冲突。
8. 保留当前 `enabled` 和 `tabTitleFontSize`，只在 `items` 末尾追加新条目。
9. 保存成功后刷新快捷入口和设置对话框的数据，并显示 `已添加到快捷网站`。

重复与上限处理：

- 按规范化后的完整 URL 判断重复；已存在时不写入，显示 `快捷网站地址不能重复`。
- 已有 12 项时不写入，显示现有文案 `最多只能添加 12 个快捷网站`。
- 本地存储写入失败时显示现有文案 `无法保存快捷网站设置`。
- 操作期间同一个“设为快捷网站”命令不可重复提交；其他标签操作保持现有行为。
- 侧边栏已经销毁时，晚到的异步结果不得渲染 DOM 或覆盖状态栏。

快捷入口总开关保持原值。如果开关关闭，网站仍会被保存并出现在设置对话框中，但顶部快捷入口不会被右键操作擅自开启。

### 加号按钮

- 加号仍位于 `tab-list` 之后并随 `tab-scroll` 滚动。
- 整体纵向占位仍为 30px，避免改变空状态起点和滚动计算。
- 实际按钮宽 44px、高 24px，上下各 3px 外边距并水平居中。
- 使用 1px `ButtonBorder` 边框和 5px 圆角，背景保持透明。
- 悬停和按下继续使用中性色背景；禁用时保留边框但文字使用 `GrayText`，不显示悬停效果。
- 保持 `title="新建标签页"`、`aria-label="新建标签页"`、`draggable=false` 和 pending 防重复逻辑。

### 底部搜索区域

- 删除 `.bottom-toolbar` 的 `border-top`，标签内容和搜索区域之间不再显示分割线。
- 保持底部工具栏固定、6px 内边距、搜索框与设置按钮 4px 间距。
- 搜索框高度仍为 32px，圆角从 6px 调整为 16px，形成稳定的胶囊形输入框。
- placeholder 和可访问名称改为 `搜索历史记录`。
- 搜索框边框、背景、清除按钮和焦点轮廓保持不变。
- 设置按钮外观不随搜索框改为胶囊形，避免两个相邻控件视觉粘连。

### 历史记录搜索

原有搜索框不再过滤当前标签列表。搜索输入、历史结果和设置按钮的结构为：

```text
bottom-toolbar
├── history-results（绝对定位在整个工具栏上方）
├── history-search-input
└── settings-button
```

搜索行为：

1. 搜索框获得焦点或在已聚焦时再次点击，以空字符串查询全部历史中的最近 20 条。
2. 输入变化后等待 100ms，再调用 `chrome.history.search({ text, startTime: 0, maxResults: 20 })`。
3. 输入期间显示 `正在搜索…`；每次查询递增 generation，晚到的旧响应直接丢弃。
4. 结果保持 Chrome 返回顺序，不在前端按访问次数或标题重新排序。
5. 过滤缺少 URL、URL 无效以及非 HTTP/HTTPS 的历史项。
6. 结果为空且输入为空时显示 `暂无历史记录`；有关键词时显示 `没有匹配的历史记录`。
7. 查询失败时在结果框显示 `无法读取历史记录`。

结果框固定在整个底部工具栏上方，与搜索框间隔 4px，横跨搜索框和设置按钮的可用宽度。最大高度为 360px，受当前视口可用高度约束，内容超过后只在结果框内部滚动。结果框不得推高、覆盖或移动底部工具栏。

每行约 30px，只显示 16px favicon 和单行标题，不显示 URL。标题为空时回退到 URL 主机名，过长标题使用省略号。favicon 优先使用当前窗口同源标签的 `favIconUrl`，其次尝试站点根目录 `/favicon.ico`，加载失败后显示标题首字符。

鼠标点击或键盘执行结果时调用 `chrome.tabs.create({ url, active: true })`。打开成功后关闭结果框并清空输入；失败时保留输入，并通过底部状态区显示 `无法打开历史记录`。

键盘与关闭行为：

- `ArrowDown`、`ArrowUp` 在结果间循环选择。
- `Enter` 打开当前选中结果。
- `Esc` 关闭结果框但保留输入内容。
- `Tab`、点击结果框和输入框之外、打开设置对话框时关闭结果框。
- 查询或打开 pending 时重复命令不得产生重复新标签。
- 搜索期间标签列表始终显示完整内容，拖动、右键菜单和实时标签事件保持可用。

## 组件与数据流

### `index.html`

- 将 `tab-search` 改为历史搜索语义，增加 `role="combobox"`、`aria-autocomplete="list"`、`aria-expanded`、`aria-controls` 和向上结果容器。
- 结果容器使用 `role="listbox"` 并保持在底部工具栏内部，CSS 负责向上定位。

### `history-search.ts`

- 定义只包含 `chrome.history.search` 的 `HistorySearchApi`，查询参数固定为 `text`、`startTime: 0` 和 `maxResults: 20`。
- 把 `chrome.history.HistoryItem` 映射为仅包含稳定 ID、标题、URL 和 favicon 候选的视图模型。
- 管理 100ms 防抖、generation、loading/empty/error 状态、结果渲染、鼠标点击、键盘选择和外部关闭。
- 通过回调请求打开 URL，不直接调用标签 API，便于独立测试。
- 暴露 `setFaviconsByOrigin()`，在当前标签创建、更新、移动、关闭后接收最新同源 favicon 映射。
- `destroy()` 清除计时器、监听器和 pending generation，销毁后的 Promise 不得修改 DOM。

### `tab-context-menu.ts`

- `TabContextCommand` 增加 `{ action: "add-shortcut"; tabId: number }`。
- 创建第三个菜单项并纳入鼠标点击、方向键循环和键盘执行逻辑。
- 菜单不读取或修改快捷网站设置，只分发命令。

### `sidebar.ts`

- 在 `onCommand` 中区分标签操作和 `add-shortcut`。
- 新增串行的快捷网站添加流程：读取设置、解析当前标签、构造候选条目、校验、保存、渲染。
- 成功保存后调用快捷网站渲染器并同步 favicon 映射。
- 使用独立 pending 标记避免重复添加；完成回调受现有 `active` 生命周期保护。
- 不把快捷网站保存错误混入标签页动作 Promise；添加成功和失败文案统一写入现有 `shortcuts` 状态槽，标签页动作继续使用 `operation` 状态槽，避免并发操作互相覆盖。
- 删除 `currentQuery`、标签过滤渲染和“搜索期间禁止拖动”的分支；标签事件始终更新完整列表。
- `SidebarDependencies` 增加只读的 `history.search` 依赖，生产入口传入 `chrome.history`。
- 初始化历史搜索控制器，向其提供 `deps.history`、同源 favicon 映射和 `tabs.create({ url, active: true })` 打开回调。
- 设置按钮打开、侧边栏滚动或页面 cleanup 时关闭或销毁历史结果框。

### `shortcut-model.ts`

- 提供一个纯函数，把现有设置、标签标题、标签 URL 和新 ID 组合为待保存设置。
- 纯函数复用 `normalizeShortcutUrl()` 和 `validateShortcutSettings()`，集中处理协议、名称回退、重复 URL、ID 冲突和 12 项上限。
- 返回新的深拷贝对象，不修改输入设置。

### `shortcut-store.ts`

- 继续作为唯一持久化入口，不新增存储键，不改变已有数据格式。

### `sidebar.css`

- 增加菜单项的 `:hover:not(:disabled)`、`:focus-visible` 和 `:active:not(:disabled)` 状态。
- 调整 `.new-tab-button` 的尺寸、外边距、边框和圆角。
- 删除 `.bottom-toolbar` 顶部边框，将 `#tab-search` 圆角改为 16px。
- 将 `.bottom-toolbar` 设为结果框的定位容器，结果框使用 `bottom: calc(100% + 4px)` 向上展开。
- 增加最大 360px 的内部滚动结果列表、30px 紧凑结果行、favicon、文字省略、hover/selected/active 和空状态样式。

## 权限与隐私

- manifest 权限从 `sidePanel`、`tabs`、`storage` 扩展为 `sidePanel`、`tabs`、`storage`、`history`。
- `history` 只用于用户主动聚焦或输入时调用本机 `chrome.history.search`。扩展不修改、删除或持久化浏览历史。
- 扩展不保存搜索关键词，不把历史结果写入 Chrome Storage，不上传历史记录或关键词。
- 商店权限理由明确说明“读取浏览历史”用于侧边栏历史搜索；安装或升级时可能出现相应 Chrome 权限提示。
- CSP、host permissions、content scripts 和远程代码策略保持不变。

## 性能

- 不增加常驻监听器数量；第三个菜单项复用菜单容器的事件委托。
- 不在标签渲染、滚动或鼠标移动期间访问 Chrome Storage。
- 只有用户执行“设为快捷网站”时才进行一次读取、一次校验和一次写入，快捷网站最多 12 项，复杂度可视为常数。
- 保存后只重新渲染最多 12 个快捷入口，不重新构建标签列表。
- 加号和悬停效果仅使用 CSS，不引入动画计时器或脚本布局测量。
- 不在扩展启动时查询历史记录，也不在内存中缓存完整历史。
- 历史查询只在聚焦或输入时发生，每次最多 20 条；100ms 防抖减少连续输入调用，generation 防止旧响应覆盖新结果。
- 历史结果 favicon 沿用图片元素候选链，不使用 `fetch`、`XMLHttpRequest` 或第三方 favicon 服务。
- 历史搜索不再重绘标签列表，标签数量不会放大每次输入的工作量。

## 可访问性

- 新菜单项使用原生 `button` 和 `role="menuitem"`。
- 三个菜单项均可通过 `Shift+F10`、方向键、`Enter`、空格和 `Esc` 操作。
- 悬停、焦点和禁用状态不只依赖单一颜色差异。
- 加号按钮保留可访问名称和清晰的键盘焦点轮廓。
- 搜索框使用明确的 `aria-label="搜索历史记录"`，圆角变化不影响语义。
- 状态栏通过现有 `role="status"` 和 `aria-live="polite"` 宣布添加成功或失败。
- 历史搜索框使用 combobox 模式维护 `aria-expanded`、`aria-controls` 和 `aria-activedescendant`。
- 历史结果容器使用 `role="listbox"`，每一行使用 `role="option"` 和 `aria-selected`；键盘选择变化必须同步辅助技术状态。
- loading、空结果和查询失败文本放在结果框内，并通过 `aria-live="polite"` 宣布，不把 URL 加入结果项可访问名称。

## 错误与并发

- 标签在点击命令前已关闭：显示 `标签页已不存在`，不写入设置。
- URL 不支持：显示 `仅支持 HTTP 或 HTTPS 地址`。
- URL 重复：显示 `快捷网站地址不能重复`。
- 达到 12 项：显示 `最多只能添加 12 个快捷网站`。
- 存储失败：显示 `无法保存快捷网站设置`。
- pending 期间再次触发添加命令直接忽略，避免重复条目。
- 页面卸载后不更新按钮、快捷入口、设置对话框或状态栏。
- 历史查询失败：结果框显示 `无法读取历史记录`，标签列表不受影响。
- 历史结果打开失败：状态栏显示 `无法打开历史记录`，输入和结果保持可重试状态。
- 历史查询晚到：generation 不匹配时直接丢弃，不覆盖当前关键词结果。
- 历史控制器销毁：清除防抖计时器并使 pending generation 失效，晚到 Promise 不更新 DOM。

## 测试策略

### 单元测试

- 右键菜单创建并按顺序呈现三个菜单项。
- 点击和键盘操作分发正确的 `add-shortcut` 标签 ID。
- 三项方向键循环、`Esc` 恢复焦点和销毁清理保持正常。
- CSS 锁定菜单 hover/focus/active 状态、加号 44×24px 边框、底栏无顶部边框和搜索框 16px 圆角。
- 快捷网站纯函数覆盖正常添加、空标题回退、HTTP/HTTPS 规范化、重复 URL、12 项上限、无效协议、ID 冲突和输入不可变。
- 历史 action 覆盖空关键词、普通关键词和严格的 `{ text, startTime: 0, maxResults: 20 }` 参数。
- 历史结果模型过滤无 URL、无效协议，覆盖空标题域名回退、20 条上限和输入不可变。
- 历史控制器覆盖聚焦查询、100ms 防抖、旧响应丢弃、loading/empty/error、鼠标打开、方向键循环、Enter、Esc、Tab、外部点击和 destroy。

### 集成测试

- 从标签右键菜单添加网站后，Storage 收到保留开关与字号的新设置。
- 快捷入口开启时立即显示新增图标；关闭时只更新设置数据，不显示顶部入口。
- 添加时优先使用当前同源标签的 `favIconUrl`。
- 重复点击 pending 命令只写入一次。
- 存储失败和无效标签显示准确错误，菜单已关闭。
- cleanup 后完成的 Promise 不修改 DOM。
- 添加快捷网站不调用 `chrome.tabs.create`、`duplicate`、`move` 或 `update`。
- 搜索历史不改变标签 DOM、不禁用拖动，也不调用标签过滤模型。
- 打开历史结果只调用一次 `chrome.tabs.create({ url, active: true })`，pending 重复执行被忽略。
- 设置按钮、标签区滚动和 cleanup 会关闭或销毁历史结果框。

### 视觉与发布验收

- 在 180×720 的浅色和深色场景检查菜单三项、hover、键盘焦点和视口边界定位。

- 检查底栏无分割线、搜索框为胶囊圆角且不与设置按钮重叠。
- 检查空输入最近 20 条、关键词、无结果、查询错误和超过可用高度时的内部滚动；结果框始终向上展开。
- 检查 favicon、单行标题、隐藏 URL，以及鼠标和键盘打开新标签。
- 检查快捷入口开启和关闭时“设为快捷网站”的可见结果。
- 完整执行类型检查、测试、构建、dist 审计和 ZIP 内容审计。
- 发布包版本为 `0.4.0`，ZIP 文件名为 `release/sidetab-lite-0.4.0.zip`。
- manifest 和商店检查清单包含 `history` 权限、权限理由和不持久化/不上传历史数据的隐私说明。

## 验收标准

- 右键菜单项在鼠标悬停、键盘焦点和按下时有清晰且克制的反馈。
- 菜单包含“复制标签页”“固定标签/取消固定”“设为快捷网站”三个命令，鼠标和键盘均可操作。
- 有效 HTTP/HTTPS 标签可以保存为快捷网站，且不改变快捷入口总开关。
- 重复、上限、无效协议、标签消失和存储失败均不会产生脏数据。
- 加号显示为居中的有边框按钮，仍位于标签列表末尾并随列表滚动。
- 搜索区域上方无分割线，搜索框为 16px 圆角，底部固定布局不变。
- 搜索框完全替换为历史记录搜索，聚焦显示最近 20 条，输入搜索全部历史，结果向上展开并在新标签页打开。
- 历史结果只显示 favicon 和单行标题，不显示 URL；鼠标、方向键、Enter、Esc 和 Tab 行为符合设计。
- 除新增必要的 `history` 权限外，不新增 host permission、远程代码或脚本网络请求。
- 版本 `0.4.0` 的构建、测试和发布包审计全部通过。
