# 标签列表新增按钮设计

## 背景与目标

SideTab Lite 当前通过标签列表展示并管理 Chrome 当前窗口中的标签页。本次变更在所有标签行下方增加一个随列表滚动的加号按钮，用于直接创建并激活一个新标签页。

目标如下：

- 加号按钮始终位于最后一个可见标签行之后，并随标签列表一起滚动。
- 点击后直接调用 `chrome.tabs.create({ active: true })`，不显示输入框或确认弹窗。
- 保持现有标签增量渲染、拖动排序、搜索和底部固定工具栏行为不变。
- 防止创建请求进行中因重复点击产生多个意外标签页。
- 发布版本从 `0.2.0` 增加到 `0.3.0`。

## 范围

### 包含

- 标签区域内部新增唯一的纵向滚动容器。
- 在标签列表之后新增独立的加号按钮。
- 新增标签页动作封装、请求状态和错误提示。
- 对应的 DOM、动作、集成、样式和发布测试。
- 生成 `0.3.0` Chrome 安装包。

### 不包含

- 输入网址、搜索词或新标签页标题。
- 自定义新标签页打开地址。
- 后台创建或创建后不激活标签页。
- 长按、右键或下拉菜单等扩展交互。
- 对新标签页进行乐观 DOM 插入。

## 页面结构

`tab-region` 继续占据侧边栏的剩余可用高度，并保持外层溢出隐藏。其内部新增 `tab-scroll`，作为标签区域唯一的纵向滚动容器：

```text
tab-region
└── tab-scroll
    ├── tab-list
    │   └── tab-row × N
    └── new-tab-button
```

`tab-list` 继续保持 `role="list"`，只包含标签行。加号按钮是列表的同级元素，不会成为列表项，也不会被标签渲染器或拖动控制器识别为标签行。

当标签列表为空或搜索结果为空时，按钮仍显示在滚动容器顶部。标签数量超过可视高度时，按钮位于内容末尾，用户滚动到最后一个标签后可以看到并使用它。

## 按钮交互与样式

按钮只显示居中的加号图标，不显示可见文字。按钮提供：

- `type="button"`
- `title="新建标签页"`
- `aria-label="新建标签页"`

按钮高度为 `30px`，与标签行一致，保持紧凑，不使用卡片式边框或大面积装饰。悬停、键盘焦点、按下和禁用状态沿用现有中性控件风格。按钮宽度适应滚动容器，不产生横向滚动条。

按钮随内容滚动，不固定在底部，也不占用搜索框与设置按钮所在的固定底部工具栏空间。

## 创建流程

1. 用户点击加号按钮。
2. 协调层立即将按钮设为禁用，避免请求未结束时再次提交。
3. 动作层调用 `chrome.tabs.create({ active: true })`。
4. 请求成功后恢复按钮；新标签页由现有 `chrome.tabs.onCreated` 事件写入标签存储并渲染。
5. 请求失败后恢复按钮，并通过现有底部状态区显示“无法新建标签页”。

侧边栏不在创建成功时直接插入标签行。Chrome 标签事件继续作为标签状态的事实来源，避免创建动作结果和 `onCreated` 事件造成重复插入。

异步结果继续使用现有操作代次机制。较早操作的完成或失败不得覆盖较新操作的状态信息。侧边栏销毁后，未完成请求不得继续修改 DOM。

## 模块边界

### `tab-actions`

- 扩展 Chrome Tabs API 依赖，加入 `create`。
- 新增 `create()` 动作，严格调用 `api.create({ active: true })`。
- 将同步异常和 Promise 拒绝统一映射为“无法新建标签页”。

### 标签区域 DOM

- 新增 `tab-scroll` 元素并承接原 `tab-list` 的纵向滚动职责。
- 新增独立 `new-tab-button`。
- `tab-list` 的标识、角色和标签行结构保持不变。

### 侧边栏协调层

- 为按钮绑定一个点击监听器。
- 创建请求期间维护按钮禁用状态。
- 复用现有动作状态与错误提示流程。
- 清理时移除监听器，并阻止异步结果继续更新按钮。

### 标签渲染与拖动模块

- 不修改标签渲染器的数据边界。
- 拖动事件仍只绑定 `tab-list`，加号按钮不是拖动源或放置目标。
- 搜索只过滤标签数据，不隐藏加号按钮。

## 性能约束

- 页面只新增一个滚动容器、一个按钮和一个固定监听器。
- 不为每个标签新增监听器或状态。
- 点击创建时只调用一次 Chrome API。
- 不因创建动作重建标签列表，不新增轮询或存储写入。
- 标签列表仍使用现有事件驱动的增量更新流程。

## 错误处理

- 同步调用异常和异步拒绝都显示“无法新建标签页”。
- 失败后按钮必须恢复可用。
- 成功但标签事件尚未到达时不进行人工补偿或重复查询。
- 页面销毁后请求完成只执行必要的内部收尾，不操作已销毁 DOM。

## 测试与验收

### 单元测试

- `tab-actions.create()` 使用精确参数 `{ active: true }` 调用一次 API。
- 同步异常和 Promise 拒绝均转换为稳定的中文错误。

### DOM 与集成测试

- `tab-scroll` 内部顺序为 `tab-list`、`new-tab-button`。
- `tab-list` 仍只包含标签行并保留 `role="list"`。
- 点击按钮时只发起一次创建请求。
- 请求进行中按钮禁用，成功或失败后恢复。
- 创建失败时底部状态区显示“无法新建标签页”。
- 空标签列表和搜索结果为空时按钮仍显示。
- 清理后点击不再调用 Chrome API，未完成请求不再更新 DOM。
- 加号按钮不参与标签拖动排序。

### 样式与响应式验收

- 滚动条属于 `tab-scroll`，标签和按钮作为一个内容整体滚动。
- 按钮不会挤压或覆盖底部固定搜索框与设置按钮。
- 180px 窄侧栏下无横向溢出，加号完整可见。
- 浅色和深色主题下悬停、焦点和禁用状态清晰。

### 发布验收

- `package.json`、`package-lock.json` 和 `manifest.json` 版本统一为 `0.3.0`。
- 权限保持为 `sidePanel`、`tabs`、`storage`，不增加新权限。
- `npm run package`、发布文件审计和确定性 ZIP 测试通过。
- 最终生成 `release/sidetab-lite-0.3.0.zip`。

## 验收标准

- 加号按钮位于最后一个标签之后，并与标签列表一起滚动。
- 点击后创建并激活一个新标签页，不显示额外交互界面。
- 创建请求期间无法重复点击，完成后恢复可用。
- 创建失败显示明确中文错误，不破坏现有标签列表。
- 空列表和搜索无结果时仍可以创建新标签页。
- 标签拖动、右键菜单、快捷网站、搜索和底部固定工具栏行为保持不变。
- 版本增加到 `0.3.0`，完整测试和打包检查通过。
