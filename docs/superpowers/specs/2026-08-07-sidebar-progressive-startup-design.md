# 侧边栏渐进启动性能优化设计

## 背景

扩展侧边栏每次打开时，底部搜索框和设置按钮会立即显示，但标签列表保持空白约 10 秒，随后全部标签一次性出现。用户的标签数量不多，因此该延迟不是列表规模导致的。

当前 `startSidebarInternal()` 先调用 `windows.getCurrent()` 获取窗口 ID，再并行调用 `tabs.query()` 和 `tabGroups.query()`，并通过 `Promise.allSettled()` 等待两者全部完成后才初始化 Store 和首次渲染。任何一个 Chrome API 慢响应都会阻塞普通标签首屏，这是标签列表长时间空白后一次性出现的代码级根因。

现有本地渲染基准中，100 个标签的中位渲染时间约为 21ms，500 个标签约为 99ms、P95 约为 149ms，进一步说明少量标签下的 10 秒延迟主要来自启动数据依赖屏障，而不是 DOM 渲染本身。

## 目标

- 使用 `windows.getCurrent({ populate: true })` 一次取得当前窗口和标签快照。
- 标签快照返回后立即渲染普通标签，不等待标签组、快捷入口设置或 favicon 缓存。
- 标签组和后台完整同步完成后原位补充分组标题、颜色、折叠状态和连续边框。
- 启动期间发生的标签和分组事件最终必须与 Chrome 真实状态收敛，不得出现重复、遗漏或过期行。
- 分组内活动标签不再显示左侧强调竖线，避免破坏连续分组容器边界。
- 标签标题默认字号从 16px 恢复为 14px，同时保留用户已保存的有效字号。
- 保持当前权限、事件驱动同步、低内存和无轮询设计。

## 非目标

- 不把标签快照持久化到 `chrome.storage`。
- 不增加骨架屏、动画或新的 DOM 布局。
- 不重写 keyed DOM 协调器，不改变标签排序、分组、搜索或拖动语义。
- 不增加权限、远程代码、轮询、长期定时器或长期标签成员缓存。
- 本次优化不升级版本、不修改发布说明、不重新打包。

## Chrome API 依据

Chrome 官方 `chrome.windows` 文档说明，`windows.getCurrent()` 接受 `QueryOptions`；当 `populate: true` 时，返回的 `Window` 包含 `tabs` 数组。扩展已声明 `tabs` 权限，因此快照中的标签可包含 URL、标题和 favicon 等现有视图所需字段。

参考：<https://developer.chrome.com/docs/extensions/reference/api/windows>

## 启动架构

### 快速首屏

启动时调用：

```ts
deps.windows.getCurrent({ populate: true })
```

返回后验证窗口 ID 和 `tabs` 数组。数据有效时立即：

1. 设置 `currentWindowId`。
2. 用标签快照初始化 `TabStore`。
3. 在空的 `TabGroupStore` 上构建列表模型。
4. 调用现有 `tabRenderer.render()` 显示可操作的普通标签。
5. 同步当前标签 favicon 给快捷入口和搜索控制器。

快捷设置、favicon 缓存和标签组查询与该流程并行运行，不得成为首屏前置条件。

### 后台一致性收敛

首屏完成后立即注册标签和标签组事件监听器，并启动一次现有完整同步。完整同步继续并行查询当前窗口的标签和标签组，在查询期间缓冲 Chrome 事件；快照应用后重放缓冲事件，再执行一次 keyed render。

这次后台同步有两个职责：

- 补齐首次普通标签视图缺少的分组标题、颜色、折叠状态和成员边界。
- 消除 `getCurrent({ populate: true })` 快照生成到事件监听器注册之间可能存在的极小事件缺口。

完整同步不得先清空已显示的列表。失败时保留首次快照，只更新稳定的状态消息。

### 降级路径

如果 `getCurrent({ populate: true })` 返回有效窗口 ID，但 `tabs` 缺失，则使用现有 `tabs.query({ windowId })` 读取首次标签快照。该降级只用于 API 返回不完整数据，不与正常路径重复查询。

窗口 ID 无效、窗口查询失败，或降级标签查询失败时，显示“无法读取当前窗口的标签页”。正常路径和降级路径都必须支持销毁检查，迟到结果不得更新 DOM。

## 数据流

启动任务拆为三个相互独立的分支：

1. **标签首屏分支**：当前窗口与标签快照 -> `TabStore` -> 普通标签首屏。
2. **快捷入口分支**：快捷设置与 favicon 缓存 -> `shortcutRenderer`。
3. **后台收敛分支**：事件订阅 -> 标签与标签组完整同步 -> 事件重放 -> 分组化列表。

`startSidebarInternal()` 不再通过一个总 `Promise.all()` 把标签可见性绑定到所有启动任务。页面可用状态以首次标签渲染为准；快捷入口和后台收敛分别管理自己的完成与错误状态。

## 分组活动标签样式

当前所有活动标签都通过 `inset 2px 0 AccentColor` 显示左侧竖线。分组成员已经使用同色左右边框构成连续容器，额外的活动竖线会破坏容器的连续视觉，因此只对带有有效分组装饰的活动标签移除该竖线。

- 未分组和固定活动标签继续显示现有左侧竖线。
- 分组内活动标签继续保留活动背景、`aria-current="page"` 和关闭按钮可见状态，仅去掉左侧竖线。
- 分组内活动标签同时被右键菜单临时选中时，继续显示完整的上下文选中轮廓，不恢复左侧竖线。
- 深色主题和强制色模式遵循相同语义，必须保留可辨识的活动背景、焦点轮廓和分组边界。
- 不修改 DOM、dataset 或事件处理；仅使用现有 `data-active` 与 `data-group-id` 收紧 CSS 选择器。

## 默认标签字号

标签标题的默认字号从 16px 恢复为 14px，设置范围仍为 12–18px。修改同时覆盖 CSS 初始变量和设置模型默认常量，避免 storage 尚未加载时先显示 16px 再跳变为 14px。

迁移规则如下：

- 新安装使用 14px。
- 缺少 `tabTitleFontSize` 字段的旧设置补为 14px。
- 已保存的 12–18px 整数值全部原样保留，包括 16px，避免覆盖用户明确选择。
- 无效字号继续按现有设置校验失败路径处理，不新增隐式纠正逻辑。
- 标签组标题现有固定 14px 样式保持不变，不读取标签标题字号设置。

## 错误与生命周期

- 标签首屏读取失败时显示标签读取错误，不阻止快捷入口继续加载。
- 标签组读取失败时保留普通标签列表，并显示分组读取错误。
- 快捷入口或 favicon 缓存读取失败时使用现有默认设置，不影响标签列表。
- 后台完整同步失败时保留最后一个一致视图，不自动循环重试。
- `destroy()` 后，窗口快照、快捷入口、标签组或完整同步的迟到结果都不得写 DOM、状态消息或 Store。
- 事件订阅和销毁保持对称，不增加常驻监听器数量。

## 性能与内存

- 首屏关键路径只等待一个当前窗口标签快照，不等待 `tabGroups.query()` 或 storage。
- 正常启动最多执行一次快速普通标签渲染和一次后台协调渲染。
- 继续复用现有 O(n) 列表模型与 keyed DOM 节点，不增加额外 DOM 包装层。
- 不保存上次标签列表，不产生陈旧首屏或新的隐私披露需求。
- 不增加 `setInterval()`、轮询、长期 `setTimeout()`、Chrome 权限或远程请求。

## 测试设计

### 启动时序

- 模拟 `getCurrent({ populate: true })` 返回少量标签，断言调用参数包含 `populate: true`。
- 让 `tabGroups.query()` 延迟 10 秒，断言普通标签已显示、可点击，分组查询完成后才补充分组标题和边框。
- 让快捷设置和 favicon 缓存延迟，断言标签首屏不等待 storage。
- 验证首次标签渲染后即可标记核心页面可用，快捷设置按钮仍按自身加载状态启用。

### 一致性与降级

- 覆盖 `tabs` 缺失时的 `tabs.query({ windowId })` 降级。
- 覆盖无效窗口 ID、窗口 API 拒绝和降级查询拒绝。
- 在首次快照与后台完整同步之间模拟标签创建、更新、移动、关闭和分组变化，断言最终 Store 与 DOM 无重复、遗漏或过期状态。
- 覆盖后台完整同步失败时保留首次标签，以及销毁后迟到结果无副作用。

### 活动样式与字号

- CSS 测试验证分组内活动标签不包含左侧 `AccentColor` 竖线，但仍保留活动背景和连续分组边框。
- 验证未分组活动标签继续显示左侧竖线。
- 验证分组内活动标签与右键临时选中叠加时只显示上下文轮廓，深色和强制色模式语义一致。
- 设置模型测试验证默认值和缺字段迁移值为 14px，已保存的 16px 及其他有效值保持不变。
- Sidebar 与 CSS 测试验证 storage 加载前后的默认字号均为 14px，不产生首屏字号跳变；标签组标题仍固定为 14px。

### 回归与验收

- 保留现有 100/500 标签观察性基准，不使用受机器波动影响的硬编码毫秒失败阈值。
- 增加结构性性能断言：首屏不得等待标签组、storage 或后台完整同步 Promise。
- 运行 Sidebar 专项测试、全部 Vitest、TypeScript、构建和 dist 审计。
- 在真实 Chrome 扩展环境验证普通标签先出现且可操作，分组状态稍后原位补齐；重复打开侧边栏不再出现约 10 秒空白列表。

## 验收标准

1. 少量标签时，每次打开侧边栏都不再因标签组或 storage 慢响应出现约 10 秒空白。
2. `tabGroups.query()` 延迟 10 秒时，普通标签仍先显示并可点击。
3. 标签组返回后视图与 Chrome 真实状态一致，不重复创建标签行。
4. API 失败和销毁路径保留稳定视图且无迟到副作用。
5. 分组内活动标签无左侧竖线，其他活动、右键选中、焦点和分组边界状态仍清晰。
6. 新安装和缺少字号字段的旧设置默认使用 14px，已保存有效字号不被覆盖。
7. 不新增权限、查询轮询、持久标签缓存、远程代码或非必要常驻资源。
