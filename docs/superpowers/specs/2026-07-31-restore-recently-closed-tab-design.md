# 打开最近关闭标签页设计

## 背景

SideTab Lite 的标签右键菜单目前支持复制、固定、设为快捷网站、分组操作和关闭下方标签页，但不能恢复最近关闭的标签页。Chrome `sessions` API 可以查询并恢复最近关闭的标签页或窗口；本功能只恢复单个标签页，不恢复整个窗口。

## 目标

- 在标签右键菜单最底部增加“打开最近关闭标签页”。
- 跳过最近关闭列表中的窗口记录，只选择最近的单个标签页。
- 菜单打开时立即显示准确的启用或禁用状态，不产生异步闪烁。
- 最近关闭列表变化后自动刷新缓存。
- 恢复操作失败时提供明确反馈。
- 保持现有标签事件为列表状态的唯一校准来源，不乐观插入标签行。

## 非目标

- 不恢复最近关闭的整个窗口或窗口内的多个标签页。
- 不展示最近关闭记录的二级列表。
- 不查询其他设备的同步会话。
- 不自行持久化关闭记录或会话 ID。
- 不修改 Chrome 的历史记录。
- 不在本设计中实现历史搜索、默认字号、新建按钮图标或启动恢复功能。

## 权限

Manifest 新增 `sessions` 权限。该权限仅用于：

- 调用 `chrome.sessions.getRecentlyClosed()` 查询本机最近关闭的标签页和窗口。
- 调用 `chrome.sessions.restore(sessionId)` 恢复选中的单个标签页。
- 监听 `chrome.sessions.onChanged` 以刷新菜单可用状态。

不新增主机权限、内容脚本或网络请求。README、商店检查清单和权限测试必须同步说明该用途。

## 最近关闭状态模块

新增一个边界清晰的最近关闭标签页控制模块，依赖最小化的 Sessions API 接口，并向 Sidebar 暴露：

```ts
type RecentlyClosedTabController = {
  getSessionId(): string | undefined;
  refresh(): Promise<void>;
  restore(sessionId: string): Promise<void>;
  destroy(): void;
};
```

模块启动时调用：

```ts
chrome.sessions.getRecentlyClosed({ maxResults: 25 })
```

按照 Chrome 返回顺序查找第一条同时满足以下条件的记录：

- 存在 `session.tab`。
- `session.tab.sessionId` 是非空字符串。

窗口记录、缺少 `sessionId` 的标签记录和损坏数据全部跳过。模块只在内存中保存一个 `sessionId`，不保存完整标签对象。

## 刷新与竞态

模块订阅 `chrome.sessions.onChanged`。每次事件触发 `refresh()`，但同一时刻最多执行一个查询：

- 查询进行中再次收到事件时，只记录还需要一次后续刷新。
- 当前查询结束后，如果期间出现过新事件，再执行一次查询最新快照。
- 较早查询结果不得覆盖较新刷新结果。
- 查询失败时清空缓存并保持控制器可用，后续 `sessions.onChanged` 可以再次刷新。
- `destroy()` 后移除监听器；已开始的查询允许结束，但不得再写入缓存或触发 UI 更新。

初始查询和事件刷新失败不阻止 Sidebar 初始化，也不写入全局启动错误。此时菜单项保持禁用。

## 性能与内存约束

- 每次查询最多读取 25 条本机会话记录，找到第一条有效标签页后不再扫描后续记录。
- 常驻状态只保存一个 `sessionId` 字符串和刷新状态标记，不保存完整 Session、Tab 或 Window 对象。
- 不使用轮询、定时刷新、后台常驻页面或额外持久化存储。
- `sessions.onChanged` 只在关闭记录真实变化时触发；并发事件通过单一查询链合并，不并行创建多个 Promise 队列。
- 最近关闭状态变化只更新菜单控制器的可用值，不调用 TabStore、不重新构建标签列表，也不触发快捷网站和历史结果渲染。
- 菜单关闭期间不保留 DOM 引用以外的会话对象；关闭菜单即清除本次绑定的 `sessionId`。
- Sidebar 销毁时同步移除唯一的 `sessions.onChanged` 监听器，并让延迟结果失效，避免监听器和闭包残留。
- 性能测试不得依赖耗时硬阈值，但必须断言事件突发时查询合并、标签渲染器未被调用以及清理后监听器数量归零。

## 右键菜单

`TabContextCommand` 增加独立命令：

```ts
{ action: "restore-recently-closed"; sessionId: string }
```

菜单项文字固定为“打开最近关闭标签页”，排列在“关闭下方标签页”之后。菜单打开时读取当前缓存：

- 有 `sessionId`：菜单项启用，并把该值绑定到本次菜单会话。
- 无 `sessionId`：菜单项禁用，不进入方向键可用项集合。

绑定到菜单会话可以避免菜单打开后后台缓存变化导致点击恢复另一条记录。关闭菜单时清除绑定值。

菜单项沿用现有微软雅黑字体、悬停、按下、焦点和禁用规则。鼠标点击、方向键、`Enter` 和空格行为与其他菜单项一致。

## 恢复流程

Sidebar 收到恢复命令后：

1. 关闭右键菜单。
2. 使用代次或忙碌状态拒绝同一恢复请求的重复执行。
3. 调用 `chrome.sessions.restore(sessionId)`。
4. 不直接写入 TabStore，等待现有 `tabs.onCreated`、`tabs.onAttached` 或重同步流程校准列表。
5. 无论成功还是失败，都请求刷新最近关闭缓存。

恢复成功时不显示额外提示。恢复失败时在状态区域显示“无法打开最近关闭标签页”。即使恢复期间 `sessions.onChanged` 已经触发，刷新逻辑仍通过合并机制保证最终缓存来自最新列表。

## 测试

自动化测试覆盖：

- 初始查询使用 `maxResults: 25`。
- 跳过窗口记录并选择最近的带 `sessionId` 标签页。
- 空列表、只有窗口、缺少 `sessionId` 和损坏数据时没有可恢复项。
- 初始查询失败不阻止 Sidebar 启动，菜单项保持禁用。
- `sessions.onChanged` 触发刷新，并发事件被合并且最终状态取最新快照。
- 事件突发期间只有一个查询同时运行，状态变化不触发标签列表重绘。
- 销毁后移除监听器，延迟查询结果不再更新状态。
- 菜单项位于最底部，启用状态、会话绑定、鼠标和键盘操作正确。
- 成功恢复只调用一次目标 `sessionId`，不直接修改 TabStore。
- 恢复失败显示明确提示并刷新缓存。
- Manifest 权限严格增加 `sessions`，无其他权限扩张。
- 现有右键菜单、标签事件、Sidebar、类型检查、构建和发布测试继续通过。
