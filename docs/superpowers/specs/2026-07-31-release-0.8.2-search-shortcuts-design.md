# SideTab Lite 0.8.2 搜索与默认入口调整设计

## 背景

SideTab Lite 0.8.1 的底部搜索框只检索 Chrome 历史记录，快捷网站默认关闭，新增标签页按钮使用本地 `add-tab.svg`。0.8.2 将收藏夹搜索结果合并到输入搜索结果中，将快捷网站默认状态调整为开启，并把新增标签页按钮恢复为替换前的 `+` 文本样式。

## 目标

- 搜索框为空且仅聚焦时，继续展示去重后的最近 20 条历史记录。
- 输入搜索内容后，前面展示最多 5 条匹配的 Chrome 收藏夹，后面补充历史记录，总数最多 20 条。
- 收藏夹和历史记录按相同规则去重，地址重复时保留收藏夹结果。
- 快捷网站在新安装、旧设置迁移和恢复默认设置后默认开启，同时保留用户明确保存的关闭状态。
- 新增标签页按钮恢复为旧版 `+` 文本与带边框样式，删除 `add-tab.svg`。
- 发布版本升级为 0.8.2，并保持性能优先原则。

## 非目标

- 不缓存完整收藏夹树，不订阅收藏夹增删改事件。
- 不在空搜索框状态下展示收藏夹。
- 不改变历史记录的候选上限、规范化规则、失焦收起或打开方式。
- 不修改快捷网站的编辑、排序、favicon 缓存和最多 12 项限制。
- 不调整新增标签页的 Chrome API 调用、滚动位置或错误处理。

## 搜索结果模型

搜索结果增加来源字段，区分 `bookmark` 与 `history`，但两种来源复用现有的标题、URL、favicon 候选和点击打开逻辑。界面不额外显示来源文字，以保持紧凑列表。

统一地址键由 URL 的主机名及端口与规范化路径组成，忽略协议、查询参数、片段标识和非根路径末尾斜杠。合并时按以下顺序处理：

1. 从匹配收藏夹中按 Chrome 返回顺序选取最多 5 条有效 HTTP/HTTPS 结果，并按统一地址键去重。
2. 从历史记录结果中跳过与已选收藏夹或已选历史记录重复的地址。
3. 用历史记录补足结果，总结果不超过 20 条。

收藏夹缺少标题时使用主机名作为标题。无效地址、文件夹节点和非 HTTP/HTTPS 地址不进入结果。

## 查询流程

搜索框为空并获得焦点时，只执行现有历史记录查询，最多读取 500 条候选记录并返回去重后的最近 20 条。

用户输入非空内容后，并行调用：

- `chrome.bookmarks.search(query)`
- 现有 `chrome.history.search()`，候选上限保持 500

两项查询完成后合并结果。继续使用现有请求序号防止快速输入时旧结果覆盖新结果，不新增定时轮询或长期缓存。

收藏夹查询失败时降级为纯历史记录结果，不阻断搜索；历史记录查询失败但收藏夹查询成功时仍展示收藏夹结果。两项查询均失败时显示现有搜索失败反馈。侧边栏销毁后，迟到的查询结果不得更新界面。

## 快捷网站默认状态

`createDefaultShortcutSettings()` 的 `enabled` 默认值改为 `true`。

设置迁移规则为：

- 存储中不存在快捷网站设置时，使用开启状态的完整默认设置。
- 旧设置缺少 `enabled` 字段时迁移为 `true`。
- 已保存的 `enabled: false` 保持关闭，不强制覆盖用户选择。
- 字段存在但不是布尔值时仍视为无效设置，并回退到完整默认设置。
- “恢复默认设置”恢复为开启状态及默认 OpenAI、Google、GitHub 三个入口。

## 新增标签页按钮

`#new-tab-button` 保留现有位置、事件、无障碍名称和 44×24px 尺寸，在按钮内容中恢复一个 `+` 字符。样式恢复为：

- `border: 1px solid ButtonBorder`
- `border-radius: 5px`
- `font: inherit`
- `font-size: 20px`
- `line-height: 1`

删除 `.new-tab-button::before` 的 SVG mask 规则和 `assets/icons/add-tab.svg`。按钮继续使用网格布局居中内容，上下外边距各 3px，所在行总高度保持 30px。

## 权限、资源与发布

Manifest 新增 `bookmarks` 权限，仅用于用户输入搜索内容时调用 Chrome 本地收藏夹搜索 API。继续保留 `sidePanel`、`tabs`、`tabGroups`、`storage`、`history` 和 `sessions`，不增加主机权限或 content script。

从构建资源列表、精确发布白名单和 SVG 校验中移除 `add-tab.svg`。`dist` 与 ZIP 的审核文件数由 15 个恢复为 14 个。

将 `manifest.json`、`package.json` 和 `package-lock.json` 的根版本统一升级为 0.8.2。输出文件为 `release/sidetab-lite-0.8.2.zip`，README、隐私政策、Chrome Web Store 检查清单和更新日志同步说明收藏夹权限、合并规则、默认开关和按钮恢复。

## 性能与内存

- 收藏夹仅在非空搜索时按需查询，不加载或缓存完整收藏夹树。
- 收藏夹与历史记录并行查询，避免串行增加等待时间。
- 合并处理上限固定为 5 条收藏夹和 20 条最终结果，历史候选上限保持 500。
- 不新增收藏夹监听器、轮询、持久化结果或长期对象。
- `+` 文本按钮不产生图片加载或 favicon 缓存条目。
- 快捷网站默认状态只改变持久化设置值，不改变渲染器生命周期或缓存策略。

## 测试与验收

### 搜索

- 空查询只调用历史记录，不调用收藏夹 API。
- 非空查询并行请求收藏夹和历史记录。
- 收藏夹最多展示 5 条，且位于历史结果之前。
- 收藏夹不足 5 条时由历史记录补足，总数最多 20 条。
- 收藏夹内部及跨来源按统一地址键去重，重复时收藏夹优先。
- 无标题收藏夹使用主机名，无效地址和文件夹节点被过滤。
- 收藏夹失败时展示历史结果，历史失败时展示收藏夹结果，两项均失败时显示错误。
- 快速输入、失焦、结果点击和销毁后的异步保护继续通过回归测试。

### 快捷网站

- 新安装默认开启并展示 OpenAI、Google、GitHub。
- 旧设置缺少 `enabled` 时迁移为开启。
- 已保存 `enabled: false` 保持关闭。
- 恢复默认设置后快捷网站开启。

### 按钮与发布

- 标记测试确认按钮包含且只包含 `+` 文本，无 SVG 子元素。
- CSS 测试确认按钮为 44×24px、1px 边框、5px 圆角、20px 字号，并且不存在 `::before` mask。
- 资源测试确认源码、`dist` 和 ZIP 均不包含 `add-tab.svg`。
- 发布测试确认版本为 0.8.2、权限精确包含 `bookmarks`、发布文件精确为 14 个。
- 执行完整类型检查、单元测试、构建、发布审计、标签渲染基准和 ZIP 内容检查。
- 在窄侧边栏中确认 `+` 上下左右居中、搜索结果紧凑、快捷网站默认可见且页面无横向滚动。

## 完成标准

- 空查询仍为 20 条历史记录，非空查询按“最多 5 条收藏夹 + 历史补足至 20 条”展示。
- 跨来源重复地址只出现一次，并优先保留收藏夹结果。
- 快捷网站默认开启，同时尊重已有关闭设置。
- 界面恢复为确认的旧版 `+` 按钮，仓库和发布产物中不存在 `add-tab.svg`。
- 版本号统一为 0.8.2，Manifest 权限与隐私说明一致，ZIP 精确包含 14 个审核文件。
- 完整自动化验证和性能基准通过，不引入持续内存增长或空闲 CPU 活动。
