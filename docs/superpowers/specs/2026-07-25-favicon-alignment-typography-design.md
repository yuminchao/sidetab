# 标签图标、对齐与字体优化设计

## 目标

在保持 30px 紧凑标签行和现有性能边界的前提下，提高网站图标命中率，统一固定与普通标签的内容起始位置，并让标签标题更接近 Chrome 原生标签的中文显示效果。同时保持搜索框和设置按钮始终固定在整个侧边栏最下方。

## 范围

本次变更只涉及标签图标回退、快捷网站图标来源、标签行水平对齐、标签标题字体、快捷网站按钮外观、相关 CSP 与发布检查。标签查询、搜索、切换、关闭、固定标签排序、快捷网站配置格式和底部工具栏功能保持不变。

## 标签页图标

标签页图标按以下顺序加载：

1. Chrome `tabs.Tab.favIconUrl`。
2. 标签页网站 `origin/favicon.ico`。
3. 标签标题首字符。

只有 `http:`、`https:` 和 `data:image/*` 图标地址可以进入图片加载流程。对于 `http://` 或 `https://` 页面，从页面 URL 提取 `origin` 后生成 `origin/favicon.ico`。`chrome://`、扩展页和其他没有 HTTP Origin 的页面不生成根目录图标地址，直接进入下一回退阶段。

图标通过 `<img>` 加载，不使用 `fetch`、XHR、第三方 favicon 服务、轮询或持久缓存。图片节点记录当前回退阶段；一次加载失败只前进一个阶段，避免重复请求和错误循环。当标签事件提供新的 `favIconUrl` 或页面 URL 时，允许该标签重新开始新的回退链。增量更新不应在标题或 active 状态单独变化时重建仍可复用的图片节点。

## 快捷网站图标

快捷网站按以下顺序加载：

1. 当前窗口内同源标签页的有效 `favIconUrl`。
2. 快捷网站 `origin/favicon.ico`。
3. 快捷网站名称首字符。

同源匹配使用规范化后的 HTTP/HTTPS Origin。多个同源标签都提供有效 `favIconUrl` 时，优先使用当前活动标签；没有活动匹配时，使用 Chrome 标签索引最小的一项。

侧边栏在内存中维护轻量的 `Origin -> favIconUrl` 映射，并在标签快照或相关标签事件变化后同步给快捷入口渲染器。该映射不写入 Chrome Storage。快捷入口总开关关闭时不渲染快捷按钮，也不产生快捷网站图标请求。

现有快捷网站存储结构中的 `icon` 字段暂时保留，用于兼容已经保存的设置；渲染器不再根据该字段选择 OpenAI、Google 或 GitHub 的本地图标。新增和编辑快捷网站仍写入兼容值，避免本次视觉调整引入存储迁移。原有本地图标资源是否从发布包移除，由实施阶段依据是否仍有其他引用决定，但不得作为运行时图标回退来源。

快捷网站按钮保留至少 32px × 32px 的稳定点击区域，去掉可见边框和常态背景，只显示图标。悬停可使用克制的状态背景，键盘聚焦必须保留清晰的焦点轮廓。图片失败后的首字符回退同样不显示按钮边框。

## 标签行对齐与字体

标签行继续保持 30px 固定高度，不显示链接、域名、第二行文字或标签间分割线。

每个标签行都保留固定宽度的图钉列。固定标签在该列显示图钉；普通标签显示等宽透明占位。这样普通标签与固定标签的 favicon、标题使用相同的列起点并纵向对齐。普通标签占位不包含可见文字，不参与辅助技术的可访问名称。

标签标题使用 14px 字号，字体优先级为：

```css
"Microsoft YaHei", "微软雅黑", "Segoe UI", system-ui, sans-serif
```

字体调整只作用于标签标题，不放大搜索框、设置按钮或设置弹窗。标题保持单行省略，关闭按钮和图标尺寸保持稳定，180px 内容宽度下不得产生横向滚动或控件裁切。

## 底部工具栏

搜索框和设置按钮必须固定在整个侧边栏最下方。标签列表独立滚动；快捷网站区和状态消息位于列表外。无论快捷网站区或状态消息显示、隐藏，底部工具栏都必须贴住视口底边，不能被自动网格排位挪动，也不能随标签列表滚动。

## 安全与权限

Manifest CSP 的 `img-src` 允许扩展本地资源、`data:`、`http:` 和 `https:`，以支持用户明确要求的 HTTP 与 HTTPS 网站图标。`script-src 'self'`、`connect-src 'none'`、`object-src 'self'`、`style-src 'self'` 和 `frame-src 'none'` 保持严格限制。

不新增主机权限、content script、远程脚本或第三方图标服务。Chrome Web Store 隐私说明应披露：浏览器渲染网站图标时可能直接向对应网站的 favicon 地址发起图片请求。

## 性能要求

- 不引入框架、后台预取、持久 favicon 缓存或定时任务。
- 快捷入口关闭时不产生快捷网站图标请求。
- 标签标题或 active 状态的增量更新不得无条件重建 favicon 节点。
- 同源图标映射只保存当前窗口的少量字符串数据，并随现有标签事件更新。
- 100 个标签页时，滚动、搜索和标签事件处理仍保持现有的增量渲染方式。

## 测试与验收

自动测试覆盖：

- `favIconUrl -> /favicon.ico -> 首字符` 的标签回退顺序。
- `同源标签 favIconUrl -> /favicon.ico -> 首字符` 的快捷网站回退顺序。
- HTTP/HTTPS Origin 派生、非 HTTP 页面跳过根目录图标、危险协议过滤。
- 多个同源标签时优先活动标签，否则选择索引最小标签。
- 标签更新后重启必要的回退链，普通 patch 不重复创建可复用图片。
- 普通标签保留图钉占位，固定与普通标签的 favicon 和标题列对齐。
- 标签标题使用 14px 微软雅黑优先字体栈。
- 快捷网站按钮无可见边框、只有图标且保留 32px 点击区域和键盘焦点。
- 搜索框和设置按钮始终固定在侧边栏最下方。
- 发布检查允许图片使用 HTTP/HTTPS，同时继续禁止 fetch、XHR、远程脚本、额外权限和未声明文件。

浏览器视觉验收覆盖 180、240、300 和 360px 宽度，以及明暗配色。必须确认：

- 固定与普通标签的 favicon 和标题纵向对齐。
- 标签标题大小接近 Chrome 原生标签，中文使用微软雅黑且不垂直裁切。
- 长标题正确省略，无水平滚动。
- 快捷网站区只展示无边框图标。
- 标签列表独立滚动，搜索框和设置按钮持续贴住整个侧边栏底部。
- 图标失败时逐级回退且不出现破图占位。

完成实现后重新生成 `dist` 和 Chrome Web Store ZIP，并验证 ZIP 内容与 `dist` 一致。
