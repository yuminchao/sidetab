# 标签组右键菜单与标题样式设计

## 背景

SideTab Lite 已支持 Chrome 标签组展示、折叠与展开，并允许从标签页右键菜单创建分组、加入分组和移出分组。目前分组标题行只通过前置圆点表示颜色，视觉识别范围较小，分组标题本身也缺少管理入口。用户需要用更紧凑、清晰的分组标题行区分标签组，并直接在侧边栏中完成分组改名、改色、解散和新增标签页，无需回到 Chrome 顶部标签栏。

本次变更保持性能优先和 Chrome 状态优先原则。界面不维护标签组的第二份业务状态，不新增轮询、常驻缓存或事件监听器；命令执行前从现有 `TabStore` 和 `GroupStore` 快照读取最新状态，成功后继续由 Chrome 标签与分组事件驱动界面更新。

## 目标

- 分组标题使用与普通标签标题相同的字体族，但固定为更紧凑的 `14px` 字号。
- 分组标题行固定为 `20px` 高，整行直接使用当前标签组颜色作为底色，并移除前置颜色圆点。
- 在分组标题行提供独立右键菜单。
- 支持在分组中新建标签页、重命名分组、修改分组颜色和解散分组。
- 颜色菜单提供 Chrome 原生的九种标签组颜色。
- 分组菜单打开期间，为触发菜单的分组标题行显示临时蓝色边框。
- 分组菜单与标签菜单互斥，避免多个上下文菜单同时存在。
- 所有操作基于执行瞬间的最新内存快照，不增加额外查询、权限或持久化状态。

## 非目标

- 不替换 Chrome 原生标签组能力，不实现扩展私有分组。
- 不新增分组排序、跨窗口移动、批量合并或分组导入导出。
- 不为解散分组增加确认弹窗或撤销入口。
- 不在重命名弹窗中同时编辑颜色。
- 不让分组标题跟随普通标签的字号设置，不新增独立的分组字号设置。
- 不使用 `chrome.contextMenus`，不新增 `contextMenus` 权限。
- 不把菜单打开状态、输入内容或临时选中状态写入存储。
- 不修改普通标签页右键菜单已确认的功能分段和同类网站操作规则。

## 分组标题样式

分组标题使用与普通标签标题相同的字体族，但采用固定的紧凑字号和行高：

```css
font-family: "Microsoft YaHei", "微软雅黑", "Segoe UI", system-ui, sans-serif;
font-size: 14px;
line-height: 20px;
```

分组标题行和主按钮均固定为 `20px` 高，上下内边距为 `0`；普通标签行继续保持现有 `30px` 高。现有“标签标题字号”设置只控制普通标签标题，分组标题始终保持 `14px`，设置界面不新增分组字号项。

分组标题行整行直接使用 `GroupViewModel.color` 对应的 Chrome 标签组颜色作为背景，不再渲染前置 `8px` 颜色圆点。主按钮的网格由“展开箭头 + 颜色圆点 + 标题”改为“展开箭头 + 标题”，保留现有展开、折叠和文字省略行为。

九种背景色沿用项目现有的 Chrome 标签组色值，深色主题继续使用现有的浅色变体。标题与展开箭头根据背景色使用预先定义的黑色或白色前景色，保证各颜色下都清晰可读，不在运行时执行颜色分析。普通状态直接显示标签组原色；悬停和按下状态只叠加轻微的明暗反馈，不把背景替换为通用悬停色。

## 组件边界

### 分组右键菜单

新增独立的 `tab-group-context-menu` 模块，只负责：

- 渲染分组菜单和颜色子菜单。
- 根据只读回调显示当前分组名称、颜色和忙碌状态。
- 处理鼠标、`Shift+F10`、焦点循环、方向键、`Enter`、空格和 `Escape`。
- 将用户选择转换为只包含 `groupId` 与必要参数的轻量命令。
- 管理菜单定位、分组标题行临时蓝色边框和统一清理。

该模块不直接调用 Chrome API，不缓存标签 ID 列表，不修改 `TabStore`、`GroupStore` 或标签 DOM。

### 分组重命名弹窗

新增独立的 `tab-group-rename-dialog` 模块，只包含分组名称输入框、“取消”和“保存”操作。它负责输入、焦点、忙碌状态和错误展示，不负责调用 Chrome API。

现有创建分组弹窗继续处理“名称 + 颜色”的新分组流程，不扩展为通用编辑弹窗，避免创建与重命名状态互相影响。

### 分组动作层

在现有分组动作层增加以下能力：

- 在指定分组末尾创建新标签页并加入分组。
- 更新分组名称。
- 更新分组颜色。
- 一次性解散指定分组。

动作层统一包装 Chrome API 错误，但不提前修改界面状态。

### 侧边栏控制器

侧边栏控制器负责命令执行瞬间重新读取 `TabStore` 和 `GroupStore`、校验目标分组是否仍存在、管理分组级忙碌状态，并复用现有错误提示与失败重同步机制。

## 右键菜单设计

分组标题行的右键菜单分为两个功能段，不显示分段标题。

第一段顺序如下：

1. 在分组中新建标签页。
2. 重命名分组。
3. 修改颜色，展开二级颜色菜单。

第二段仅包含：

1. 解散分组。

两段之间只有一条 `role="separator"` 分割线。分割线无文本、不可聚焦、不响应鼠标事件，也不进入方向键导航序列。

主菜单和颜色子菜单沿用标签右键菜单的边框、圆角、阴影、微软雅黑字体、悬停和按下反馈，并统一使用自适应浅灰底色：

```css
background: color-mix(in srgb, CanvasText 4%, Canvas);
```

鼠标在分组行的展开箭头、标题文字或其他空白区域上右键，均打开同一个分组菜单。键盘聚焦分组标题主按钮后按 `Shift+F10`，行为与鼠标右键一致。

## 颜色子菜单

“修改颜色”展开二级菜单，按固定顺序展示 Chrome 原生九种标签组颜色：

1. 灰色 `grey`
2. 蓝色 `blue`
3. 红色 `red`
4. 黄色 `yellow`
5. 绿色 `green`
6. 粉色 `pink`
7. 紫色 `purple`
8. 青色 `cyan`
9. 橙色 `orange`

每个菜单项同时展示颜色色块和中文颜色名称。当前颜色显示选中标记并禁用，鼠标与键盘均不得重复派发命令。选择其他颜色后立即关闭菜单并提交修改，不再打开确认弹窗。

颜色子菜单展开时，分组标题行的临时选中边框继续保留。左右方向键负责进入或退出子菜单，上下方向键只在可用颜色项之间循环。

## 临时选中状态

分组菜单打开时，触发菜单的分组标题行增加临时 `data-context-selected="true"` 状态，并通过不占布局空间的内描边显示完整 1px 蓝色边框：

- 浅色主题：`#1a73e8`。
- 深色主题：`#8ab4f8`。

临时状态不替换标签组底色，不使用左侧强调线，不改变分组标题行的宽度、高度、内边距或文字位置。它只存在于当前分组标题行 DOM，不写入 `GroupStore`，也不设置表示真实选择的 ARIA 状态。蓝色分组的底色可能与临时边框接近，因此在蓝色边框内侧增加一条不占布局空间的 `Canvas` 对比衬线，确保边界可辨；衬线只辅助对比，不改变蓝色边框本身。

以下任一情况发生时必须立即清除临时状态：

- 执行任意菜单命令。
- 点击菜单外部或按 `Escape`。
- 标签列表滚动或窗口缩放。
- 目标分组被删除、解散或替换。
- 在其他标签或分组上打开右键菜单。
- 菜单组件或侧边栏销毁。

标签右键菜单和分组右键菜单互斥。打开其中一个前，先调用另一个的统一关闭方法，确保旧目标的临时边框和事件资源同步清理。

## 重命名交互

选择“重命名分组”后关闭右键菜单并打开专用弹窗：

- 标题为“重命名分组”。
- 输入框预填当前分组名称；未命名分组预填空字符串。
- 打开后选中名称文字，便于直接覆盖输入。
- 提交时去除名称首尾空格；结果允许为空，空值表示未命名分组。
- “取消”关闭弹窗且不执行任何 API。
- “保存”进入忙碌状态，输入框和操作按钮暂时禁用，防止重复提交。
- 保存失败时弹窗保持打开、保留用户输入并展示错误，允许再次提交或取消。

控制器在提交时重新确认目标分组仍存在。分组已被移除时静默关闭弹窗，不调用 Chrome API。

## 动作流程

### 在分组中新建标签页

执行时重新读取目标分组和当前窗口的完整标签快照，找到该分组最后一个标签的位置。随后：

1. 调用一次 `chrome.tabs.create()`，在分组最后一个标签之后创建并激活 Chrome 新标签页。
2. 取得新标签 ID 后，调用一次 `chrome.tabs.group({ tabIds: newTabId, groupId })` 将其加入原分组。

成功后不直接插入标签 DOM，由现有 Chrome 事件同步真实状态。

若创建失败，提示“无法在分组中新建标签页”。若标签页创建成功但加入分组失败，保留已经创建的普通标签页，提示“标签页已创建，但无法加入分组”，并触发一次现有的标签与分组状态重同步，不尝试自动关闭该标签页。

### 重命名分组

执行时调用一次：

```ts
chrome.tabGroups.update(groupId, { title })
```

成功后关闭弹窗并等待 Chrome 分组事件更新标题。失败时提示“无法重命名标签组”，保留弹窗和输入内容，并触发一次状态重同步。

### 修改颜色

执行时调用一次：

```ts
chrome.tabGroups.update(groupId, { color })
```

成功后等待 Chrome 分组事件更新颜色。失败时提示“无法修改标签组颜色”，并触发一次状态重同步。执行前若目标颜色已是当前颜色，则静默结束且不调用 API。

### 解散分组

执行时从最新 `TabStore` 快照收集目标分组内的全部标签 ID，包括折叠状态下未渲染为普通行的标签，并调用一次：

```ts
chrome.tabs.ungroup(tabIds)
```

该操作不关闭标签页、不改变标签顺序、不打开确认弹窗。Chrome 会在最后一个标签移出后删除空分组。目标分组不存在或没有可处理标签时静默结束。失败时提示“无法解散标签组”，并触发一次状态重同步。

## 并发与状态同步

- 使用按 `groupId` 记录的短生命周期忙碌集合，阻止同一分组的命令重复提交。
- 分组忙碌时，其菜单命令和重命名保存操作不可再次执行。
- 命令只携带 `groupId`、目标颜色或名称，不保存菜单打开时的标签 ID 数组。
- 执行前重新读取最新 `GroupStore` 和 `TabStore`；分组已不存在时静默结束。
- Chrome 事件到达前不提前更新分组标题、颜色、成员关系或 DOM。
- 失败后最多触发一次现有的合并重同步，不循环重试、不轮询。
- 侧边栏销毁后，迟到的异步结果不得更新界面、重新打开弹窗或遗留忙碌状态。

## 错误处理

- 新标签页创建失败：提示“无法在分组中新建标签页”。
- 新标签页已创建但加入分组失败：保留普通标签页，提示“标签页已创建，但无法加入分组”。
- 重命名失败：提示“无法重命名标签组”，保留弹窗内容。
- 修改颜色失败：提示“无法修改标签组颜色”。
- 解散失败：提示“无法解散标签组”。
- 操作开始前目标分组已不存在：静默结束。
- 状态重同步失败：保留当前可用视图和原错误提示，不重试。

错误文案不包含网址、标签标题或其他浏览数据，不向外部服务上报。

## 性能与内存

- 菜单打开只读取当前分组模型和忙碌状态，不调用 `chrome.tabs.query()` 或 `chrome.tabGroups.query()`。
- 新建标签和解散分组仅在命令执行时对现有标签快照进行一次 O(n) 扫描。
- 重命名和修改颜色无需扫描全部标签。
- 不新增分组成员索引、菜单结果缓存、定时器、轮询或 Chrome 事件监听器。
- 颜色列表为九项静态定义，不随菜单打开重复构建业务缓存。
- 菜单、子菜单、弹窗和临时数组只在交互期间存活，关闭后清理 DOM 引用和事件处理器。
- 成功路径使用固定次数的 Chrome API 调用；解散分组无论成员数量多少均只调用一次 `chrome.tabs.ungroup()`。

## 权限与隐私

本功能只使用扩展已有的 `tabs` 和 `tabGroups` 权限，不新增权限、主机权限、content script、网络请求或远程代码。分组名称、颜色和标签成员只在本地用于当前操作，不写入扩展存储、不上传、不记录日志。

## 测试策略

### 分组标题样式

- 验证普通标签行保持 `30px`，分组标题行和主按钮固定为 `20px`。
- 验证分组标题使用微软雅黑字体族、固定 `14px` 字号和 `20px` 行高。
- 修改普通标签标题字号后，分组标题仍保持 `14px`，且设置界面没有新增分组字号项。
- 验证分组标题行直接使用当前分组颜色作为整行背景，DOM 不再包含前置颜色圆点。
- 验证九种颜色在浅色和深色主题下都有清晰的标题与箭头对比度。
- 验证悬停和按下反馈保留分组原色，不使用通用背景替换。
- 在最小侧边栏宽度下，分组名称不与展开箭头或相邻内容重叠。

### 分组右键菜单

- 验证四个菜单项的文字、顺序和 `role`。
- 验证主菜单只有一条分割线，且不可聚焦、不响应点击、不进入方向键导航。
- 验证主菜单和颜色子菜单使用自适应浅灰底色、微软雅黑字体和现有悬停/按下反馈。
- 验证右键点击分组行不同子元素以及 `Shift+F10` 均打开同一菜单。
- 验证标签菜单与分组菜单互斥，切换菜单时旧目标状态被完整清理。
- 验证菜单打开期间分组标题行显示完整 1px 蓝色内描边，关闭后恢复且没有布局跳动。
- 验证蓝色分组的临时边框具有对比衬线，在相同或相近底色上仍可辨识。

### 颜色子菜单

- 验证九种颜色的顺序、色块、中文名称和 API 枚举值。
- 验证当前颜色显示选中并禁用，不派发重复命令。
- 验证鼠标、上下方向键、左右方向键、`Enter`、空格和 `Escape` 行为。
- 验证子菜单展开时分组标题行临时蓝色边框保持可见。

### 重命名弹窗

- 验证预填当前名称、空名称、文字选中、取消和保存。
- 验证提交时去除首尾空格，并允许提交空名称。
- 验证忙碌期间禁止重复提交。
- 验证成功后等待 Chrome 事件更新界面。
- 验证失败后保留弹窗、用户输入和错误提示。
- 验证弹窗打开后分组被删除时静默关闭。

### 动作层与控制器

- 在分组最后一个标签之后创建并激活新标签，再将其加入原分组。
- 创建失败时不调用分组 API；加入分组失败时保留普通标签并只触发一次重同步。
- 重命名和改色分别只调用一次 `chrome.tabGroups.update()`。
- 解散分组收集全部成员，包括折叠分组中的标签，并只调用一次 `chrome.tabs.ungroup(ids)`。
- 解散分组不关闭标签、不改变顺序、不显示确认弹窗。
- 菜单打开后状态发生变化时，命令使用执行瞬间的最新快照。
- 同一分组的重复命令被阻止，不同分组的操作不互相锁定。
- Chrome 事件到达前不提前修改 Store 或 DOM。
- 侧边栏销毁后，迟到结果不更新界面且所有临时引用被释放。

### 回归与视觉检查

- 运行类型检查、完整测试、构建、发布目录审计和标签渲染性能基准。
- 在 Chrome 最小侧边栏宽度和常规宽度检查菜单定位、子菜单方向和文本溢出。
- 在浅色与深色主题检查菜单底色、分割线、临时蓝色边框、焦点和禁用状态。
- 验证分组折叠/展开、标签右键菜单、拖动排序、中键关闭和普通标签激活行为不回归。

## 发布要求

本功能不单独触发打包。与已确认的同类网站标签操作一起完成开发和验证后，只执行一次发布打包。打包时必须提升当前扩展版本号，并在仓库根目录 `E:\java\sidebar\update.log` 中记录本次分组右键菜单、分组标题样式和同类网站标签操作的对应更新内容。发布 ZIP 只包含通过审计的扩展运行文件。

## 验收标准

- 分组标题使用与普通标签相同的微软雅黑字体族，固定为 `14px`，不受普通标签字号设置影响。
- 分组标题行固定为 `20px`，低于普通标签的 `30px`，整行直接显示标签组颜色且没有前置颜色圆点。
- 分组标题行右键菜单按两段展示“在分组中新建标签页”“重命名分组”“修改颜色”和“解散分组”。
- 颜色子菜单完整提供九种 Chrome 原生颜色，当前颜色不可重复提交。
- 菜单打开期间，目标分组标题行显示不引发布局跳动的完整蓝色边框；菜单关闭后立即清除。
- 新标签页在分组末尾创建并激活；加入分组部分失败时保留该标签页并给出明确反馈。
- 重命名支持空名称，失败后保留输入内容。
