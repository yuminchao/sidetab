# Chrome 外观设置入口与设置图标优化设计

## 背景

SideTab Lite 运行在 Chrome 原生侧边栏中。用户希望更方便地调整整个 Chrome 侧边栏位于浏览器左侧还是右侧，同时将扩展底部的设置入口简化为纯齿轮图标，并让标签右键菜单统一使用微软雅黑。

侧边栏左右位置由 Chrome 外观设置控制。本次不读取、不保存也不展示当前位置，只在扩展设置中给出清晰提示和 `chrome://settings/appearance` 跳转入口，由用户在 Chrome 原生设置页完成修改。

参考资料：[Chrome 帮助：管理侧边栏](https://support.google.com/chrome/answer/13156494)。

发布版本从 `0.5.0` 升级为 `0.6.0`。

## 目标

- 在扩展设置中说明侧边栏位置需要前往 Chrome 外观设置修改。
- 提供直接打开 `chrome://settings/appearance` 的入口。
- 将底部设置入口改为只显示齿轮的图标控件，不再呈现普通按钮外观。
- 将标签右键菜单字体统一为微软雅黑，并保留合理的系统字体回退。
- 不增加扩展权限、API 查询、常驻监听器或启动阶段额外工作。

## 非目标

- 不读取或展示 Chrome 侧边栏当前位于左侧还是右侧。
- 不在扩展中保存左侧或右侧配置。
- 不尝试通过未公开 API、页面脚本或自动点击修改 Chrome 设置。
- 不调整扩展内部标签列表、快捷网站或底部工具栏的左右排列方式。
- 不改变字号和快捷网站配置的数据格式。
- 不提高 `minimum_chrome_version`，不增加 host permission 或 content script。

## 方案设计

设置对话框只提供静态说明和 Chrome 外观设置入口。该方案没有浏览器版本差异，不会产生与 Chrome 真实状态不一致的本地配置，也不会为一个低频入口增加异步查询和状态管理。

不采用以下方案：

- 不调用 `chrome.sidePanel.getLayout()`，因为本次不需要展示当前位置。
- 不保存左侧或右侧选项，因为扩展无法通过该值直接修改 Chrome 设置。
- 不提高最低 Chrome 版本，现有 Chrome 114+ 用户继续获得一致体验。

## 交互设计

### Chrome 外观设置入口

在设置对话框“外观”区域的“标签标题字号”下方新增一行：

```text
侧边栏位置    请在 Chrome 外观设置中修改  ↗
```

- 行标题固定为“侧边栏位置”，指整个 Chrome 侧边栏，而不是扩展内部布局。
- 提示文案固定为“请在 Chrome 外观设置中修改”。
- 右侧使用紧凑的外部跳转图标控件，`title` 和 `aria-label` 均为“打开 Chrome 外观设置”。
- 点击后通过 `chrome.tabs.create` 打开 `chrome://settings/appearance`。
- 打开成功后保持扩展设置对话框现状，不自动关闭对话框。
- 打开失败时复用现有设置错误区域，显示“无法打开 Chrome 外观设置”。
- 该行不参与表单保存、取消或恢复默认，不产生本地持久化数据。
- 提示和入口始终显示，不根据 Chrome 版本或当前位置改变。

### 底部齿轮入口

- 保留原生 `button`、32×32px 稳定点击区域、`title`、`aria-label` 和键盘激活能力。
- 视觉上只显示齿轮：默认无边框、无背景、无阴影，不再呈现普通按钮轮廓。
- 鼠标悬停和按下只调整图标颜色或透明度，不改变布局尺寸。
- `:focus-visible` 保留清晰的焦点轮廓，确保键盘用户能够识别当前焦点。
- 设置按钮语义从“快捷网站设置”统一为“设置”，因为对话框同时包含外观与快捷网站配置。

### 标签右键菜单字体

- 菜单容器及菜单项使用 `"Microsoft YaHei", "微软雅黑", "Segoe UI", system-ui, sans-serif`。
- 字体调整不改变现有菜单项高度、顺序、悬停反馈、键盘导航和禁用状态。
- 系统没有微软雅黑时依次回退到 Segoe UI 和系统无衬线字体。

## 架构与数据流

### `index.html`

- 在外观设置区新增侧边栏位置说明、提示文本和外部跳转按钮。
- 外部跳转按钮使用原生 `button type="button"`，避免触发表单提交。
- 将底部齿轮按钮的 `title` 与 `aria-label` 改为“设置”。

### `sidebar.ts`

- 获取外部跳转按钮并注册点击事件。
- 点击后调用 `deps.tabs.create({ url: "chrome://settings/appearance", active: true })`。
- 使用单独的 pending 状态防止连续点击产生多个 Chrome 设置标签页。
- 打开失败时通过设置对话框现有错误区域展示稳定文案。
- cleanup 时移除监听器；页面失效后晚到的异步结果不得更新 DOM。
- 不新增 `sidePanel` 依赖，不调用 Chrome Side Panel API。
- 不修改快捷网站设置模型、存储键或保存流程。

### `sidebar.css`

- 新增位置说明行、提示文本和外部跳转图标的紧凑布局。
- 提示文本允许收缩，最窄侧边栏中可以自然换行，不得覆盖跳转图标。
- 为底部齿轮增加专用类或 ID 样式，覆盖共享按钮的边框、背景和阴影，同时保留固定尺寸与焦点轮廓。
- 在 `.tab-context-menu` 上设置微软雅黑字体栈，使动态创建的全部菜单项继承一致字体。

## 状态与错误处理

- 默认状态只显示静态提示，不执行任何 Chrome API 调用。
- 点击跳转入口时临时禁用该入口，避免 pending 期间重复创建标签页。
- Chrome 设置页打开成功后恢复入口可用状态。
- `chrome.tabs.create` 拒绝或同步抛错时恢复入口，并显示“无法打开 Chrome 外观设置”。
- 打开失败不关闭设置对话框，不影响字号和快捷网站表单继续使用。
- 页面销毁后不更新按钮状态或错误区域。

## 兼容性与权限

- `minimum_chrome_version` 继续为 `114`。
- `tabs` 已是现有权限，本功能不增加 manifest 权限。
- 不调用 `chrome.sidePanel.getLayout()`，没有 Chrome 140 版本分支。
- 不读取或修改 Chrome 设置页面 DOM，不注入脚本，不使用私有 API。
- 外观设置 URL 固定为 `chrome://settings/appearance`，仅在用户主动点击时创建标签页。

## 性能

- 设置对话框打开时不查询 API、不读取 Storage，也不进行网络访问。
- 仅在用户点击入口时创建一个 Chrome 设置标签页。
- 不轮询、不注册 Chrome 事件监听器、不持久化位置。
- 齿轮和菜单字体仅通过 CSS 调整，不增加脚本布局测量或动画计时器。

## 可访问性

- 底部齿轮继续使用原生按钮，键盘、屏幕阅读器和触摸操作行为不变。
- 纯图标控件保留 `aria-label="设置"`，外部跳转图标保留 `aria-label="打开 Chrome 外观设置"`。
- 视觉按钮边框被移除后，仍保留 `:focus-visible` 焦点轮廓，不能只通过颜色表达焦点。
- 侧边栏位置提示使用可见文本，不以外部跳转图标单独传达修改方式。
- 设置错误继续通过现有 `role="alert"` 区域通知辅助技术。

## 测试策略

### 单元与集成测试

- 点击位置入口调用一次 `tabs.create({ url: "chrome://settings/appearance", active: true })`。
- pending 期间重复点击不创建第二个设置标签页。
- 打开成功后入口恢复可用。
- 打开失败时显示“无法打开 Chrome 外观设置”，入口恢复可用，其他表单仍可操作。
- cleanup 后打开结果不得修改 DOM。
- 设置保存负载不包含侧边栏位置字段。
- 扩展启动和设置对话框打开均不调用 Side Panel API。

### DOM、样式与发布测试

- HTML 包含固定提示文案、外部跳转控件及正确的可访问名称。
- 底部设置入口仍为原生按钮，默认无边框、无背景、无阴影，并保留 32×32px 点击区与焦点轮廓。
- `.tab-context-menu` 使用约定的微软雅黑字体栈，菜单项继续继承现有交互样式。
- 在 180px 最窄侧边栏宽度检查位置提示可以换行，且不与跳转图标重叠或溢出。
- 在浅色、深色以及键盘导航场景检查齿轮和跳转图标状态。
- 完整执行类型检查、自动化测试、构建、dist 审计与 ZIP 内容审计。
- `manifest.json`、`package.json`、锁文件、README 和测试中的版本统一升级为 `0.6.0`。
- 发布包文件名为 `release/sidetab-lite-0.6.0.zip`。

## 验收标准

- 设置对话框明确提示用户在 Chrome 外观设置中修改侧边栏位置。
- 用户可以一键打开 `chrome://settings/appearance`，失败时获得稳定反馈。
- 扩展不读取、不保存、不展示侧边栏当前位置，也没有 Chrome 140 版本分支。
- 底部设置入口视觉上只显示齿轮，同时支持鼠标、键盘和屏幕阅读器。
- 标签右键菜单使用微软雅黑字体栈，既有菜单交互和布局不发生回归。
- 本功能不增加权限、不提高最低 Chrome 版本，版本 `0.6.0` 的测试、构建和发布包审计全部通过。
