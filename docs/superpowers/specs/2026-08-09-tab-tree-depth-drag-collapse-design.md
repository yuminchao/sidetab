# 标签树层级拖放与活动树折叠设计

## 背景

当前标签树需要同时表达排序和父子关系，但拖放反馈必须让用户在释放鼠标前明确知道结果：横线表示成为目标的同级，整行高亮表示成为目标的直接子节点。叶子节点前方也需要与父节点展开箭头对应的层级标记。此外，活动标签路径会自动展开，用户无法主动收起包含活动标签的树。

本设计增加三项相互配合的能力：叶子节点圆点、通过纵向命中区域选择同级或子级关系的拖放，以及活动标签所在树的手动折叠。实现继续以 Chrome 标签顺序和 `openerTabId` 为基础，通过当前会话内的显式父关系覆盖表达用户拖放意图。

## 目标

- 父节点和叶子节点使用同一层级槽位，快速区分可展开节点与树末端。
- 纵向命中区域同时决定排序关系：边缘定位线表示成为目标同级，中间整行高亮表示成为目标直接子节点。
- 支持移动单个叶子或整棵子树，并允许提升到祖先层级、根级或放入有效父节点。
- 允许手动折叠包含活动标签的树，并明确提示折叠树内存在活动标签。
- 保持固定标签、Chrome 原生标签组、窗口和循环检测边界。
- 拖放热路径不增加 Chrome 查询、轮询或整表重复渲染。

## 非目标

- 不修改 Chrome 不可写的 `openerTabId`。
- 不把手动父关系保存到跨浏览器会话的长期存储。
- 不支持一次拖放创建超过四级的手动深度。
- 不改变 Chrome 原生标签组标题的“拖入即加入分组”语义。
- 不为叶子圆点增加按钮、菜单或其他交互。
- 不新增权限、远程代码、网络请求或常驻定时任务。

## 术语

- **深度**：根标签为 0，直接子标签为 1，依次递增。
- **参考标签**：当前命中的可见普通标签，或行间距、列表末尾所邻近的可见普通标签。
- **同级关系**：拖动子树根成为参考标签的同级节点，反馈为参考标签前或后的定位线。
- **子级关系**：拖动子树根成为参考标签的直接子节点，反馈为参考标签整行高亮。
- **活动后代**：当前 Chrome 活动标签位于某个父节点的后代集合中，但父节点本身不是活动标签。

## 叶子节点标记

父节点继续在现有 12px 层级槽位显示展开箭头。深度大于 0 且没有子节点的叶子标签在相同槽位显示 4px 实心圆点：

- 颜色使用 `GrayText`，强制颜色模式下继续使用系统颜色。
- 圆点设置 `aria-hidden="true"`，没有按钮语义、焦点、悬停态或点击行为。
- 深度为 0 且没有子节点的普通根标签不显示圆点。
- 圆点不改变 favicon、标题、关闭按钮的位置，不改变 30px 标签行高。
- 叶子变为父节点时，圆点替换为展开箭头；最后一个子节点移除后，展开箭头替换为圆点或根级空槽。

实现优先复用现有不可见的固定图标槽位或同等布局槽位，不为每行增加无必要的外层容器。

## 关系拖放

### 纵向命中与关系

普通标签行沿纵向划分为三个稳定命中区：

- 上方 25% 显示目标行之前的定位线，释放后拖动子树根成为目标同级并排在目标之前。
- 中间 50% 高亮目标整行，释放后拖动子树根成为目标的最后一个直接子节点。
- 下方 25% 显示目标行之后的定位线，释放后拖动子树根成为目标同级并排在目标完整子树之后。

行间距不产生整行高亮，只根据更近的相邻标签显示同级定位线；距离相同时优先使用上方标签，避免边界抖动。列表末尾和新增标签按钮区域也只显示同级定位线，不提供创建子节点的命中区。

横向输入不参与关系或层级判定。无论指针横向移动多少，只要纵向命中区不变，放置关系和反馈就保持不变。

### 关系解析与深度约束

同级关系继承参考标签当前的父节点和深度；子级关系将参考标签设为新父节点，深度为参考标签深度加一。两种关系均须满足以下约束：

- 拖动子树放置后的最大深度不得超过四级。
- 不允许把节点或子树放入自身后代。
- 固定标签、原生标签组、窗口和父关系边界必须有效。
- 无法形成有效关系或不会产生变化时，不显示定位线或整行高亮，也不能执行放置。

### 放置反馈

定位线只表达同级排序，整行高亮只表达直接子关系：

- 定位线缩进仅反映参考标签已经存在的深度，不预览或创造新深度；缩进从逻辑行首计算，从右到左界面中方向正确镜像，但横向输入仍不参与关系判定。
- 上方定位线位于目标行之前；下方定位线位于目标完整子树最后一个可见后代之后。目标折叠导致后代不可见时，定位线回退到目标行之后。
- 子级高亮覆盖目标整行，不与定位线同时显示。
- 定位线不使用过渡动画，避免拖动时产生滞后。
- 末尾外部区域的同级定位线固定在列表内容末尾，不随鼠标在空白区域上下移动。
- 浅色、深色和强制颜色模式下，定位线与整行高亮均须清晰可辨。

### 放置结果

- 拖动叶子节点时，只移动该标签并更新其显式父关系。
- 拖动父节点时，整棵可见或折叠子树连续移动；只改变子树根节点的父关系，后代相对层级和顺序保持不变。
- 同级放置时，子树根继承参考标签的父关系；参考标签为根节点时删除子树根的手动父关系。
- 子级放置时，记录子树根节点到参考标签的会话级覆盖；后代父关系保持不变。
- `after` 同级放置与子级放置的真实 Chrome 排序位置都在参考标签完整子树之后，确保先序结构连续。子级放置在树关系上仍是参考标签的最后一个直接子节点。
- 最终位置和父关系均未变化时视为无操作，不调用 Chrome API，也不写存储。
- 整行高亮创建直接子节点成功后才自动展开折叠父节点，确保结果立即可见；边缘同级定位线投放不展开折叠目标。

## 边界规则

- 固定标签保持根级，树节点不得跨越固定标签区域。
- Chrome 原生标签组保持独立连续块，树关系选择不介入分组标题和组内成员。
- 拖到原生分组标题继续表示加入该分组；不得同时建立树父关系。
- 手动父关系不得跨窗口，标签附加到其他窗口后按目标窗口状态重新计算。
- 折叠子树的隐藏后代仍参与循环检测、子树连续移动和真实 Chrome 索引计算。
- 标签 ID 被 Chrome 替换时，父关系覆盖、折叠状态和活动后代状态使用替换后的 ID。

## 活动标签所在树的折叠

用户可以折叠活动父节点的子树，也可以折叠包含活动后代的祖先节点。手动折叠优先于活动路径自动展开：

- 手动折叠状态按窗口保存在当前浏览器会话中。
- 普通标签激活事件、侧边栏重新打开和会话状态恢复不强制展开活动路径。
- 活动标签被折叠隐藏时，最近可见的折叠祖先展开箭头使用 `AccentColor`。
- 包含活动后代的父节点不使用活动标签的淡黄色背景，也不设置 `aria-current`。
- 该父节点的展开按钮辅助名称为“展开子标签，包含当前标签”。
- 活动父节点本身仍使用正常活动标签样式，折叠仅隐藏其后代。

仅以下明确产生新可见结果的操作自动展开路径：

1. 用户通过整行高亮把标签或子树创建为折叠父节点的直接子节点，且投放成功。
2. 新建并激活一个子标签。

后台创建但未激活的子标签不自动展开；仅切换到已有隐藏标签也不覆盖用户的手动折叠决定。

## 状态与持久化

手动父关系继续按窗口保存在 `storage.session`，使用 `tabId -> parentTabId` 覆盖表达当前会话内的用户意图。折叠状态与父关系覆盖必须作为同一窗口树状态一致恢复：

- 不写入 `storage.local` 或其他长期数据库。
- 不修改 `openerTabId`，没有覆盖时继续使用 Chrome 原生打开来源。
- 标签拖到根级、父标签关闭或关系失效时清理对应覆盖。
- 标签 ID 替换时迁移子节点 ID和父节点 ID。
- 写入继续串行化，避免快速拖放或折叠导致旧快照覆盖新状态。

## 性能要求

- 树构建、父关系校验和子树边界计算保持 O(n)。
- 拖动开始时可以保存当前可见行和深度快照，不在每个 `dragover` 事件中扫描完整 DOM。
- 行间空隙定位保持 O(log n) 或更优；直接命中标签行时使用常数时间目标解析。
- 命中区解析、关系校验、定位线和整行高亮更新不得触发完整标签列表渲染。
- 叶子圆点复用现有行结构或伪元素，不增加每次拖动的 Chrome API 调用。
- 不新增轮询、定时刷新或长期全量标签缓存。

## 可访问性与键盘行为

- 父节点展开按钮继续支持现有键盘焦点、左右方向键和 `aria-expanded`。
- 叶子圆点纯装饰，不进入 Tab 顺序。
- 折叠隐藏活动标签时，只有真实活动标签保留 `aria-current="page"`；不可把该属性转移给祖先。
- 包含活动后代的展开按钮通过辅助名称表达状态，不只依赖颜色。
- 拖放定位线为视觉反馈，不增加错误的列表项或按钮语义。

## 失败与并发处理

- Chrome 移动、分组调整或会话写入失败时，重新同步当前窗口真实标签状态，不提前提交错误父关系。
- 拖放执行期间禁止重复提交；完成后根据最新标签快照重新计算树。
- 拖动过程中源节点、参考节点或父节点被移除时取消操作并清除定位线。
- 窗口切换、滚动、尺寸变化或页面销毁继续取消当前拖动，避免使用过期几何信息。

## 验收场景

1. 根级普通标签无圆点；一级至四级叶子显示圆点；父节点显示展开箭头。
2. 叶子新增首个子节点后圆点变为箭头；最后一个子节点关闭后恢复圆点。
3. 指针命中标签上方 25% 或下方 25% 时只显示同级定位线；命中中间 50% 时只显示整行高亮，横向移动不改变反馈或结果。
4. Root 到 Root、Root 到 Child、Child 到 Child、Child 到 Root 四种组合均支持同级定位线和子级高亮；结果深度不超过四级。
5. 上方定位线把子树放在目标同级之前；下方定位线把子树放在目标完整子树之后；整行高亮把子树放为目标最后一个直接子节点，其真实排序位置同样位于目标完整子树之后。
6. 拖动父节点时整棵子树连续移动，后代相对顺序和层级不变。
7. 行间距和列表末尾只显示同级定位线，不出现整行高亮，也不创建父子关系。
8. 整行高亮创建直接子节点成功后自动展开折叠父节点；边缘同级定位线投放、失败或取消投放以及普通活动标签切换都不展开手动折叠树。
9. 活动后代被隐藏时，最近可见折叠祖先箭头使用强调色和正确辅助名称，父行不冒充活动标签。
10. 固定标签、原生标签组、跨窗口、自身子树、循环和无变化目标均被拒绝且无副作用。
11. 500 个标签下拖放反馈保持流畅，不增加逐帧全 DOM 扫描或 Chrome 查询。
12. 浅色、深色、强制颜色以及从右到左界面下，圆点、箭头、定位线和整行高亮均清晰；RTL 定位线从逻辑行首正确镜像，横向移动不改变拖放关系。

## 测试决策

- 模型测试覆盖 `reference + relation` 解析、四种 Root/Child 组合、深度上限、完整子树末尾计算和循环拒绝。
- 拖放控制器测试使用真实行矩形验证上 25%、中 50%、下 25%、行间距和外部空白区域，并验证横向移动不改变结果、不使用过期目标反馈。
- 侧边栏集成测试覆盖叶子、父节点、整棵子树、折叠目标、固定区和原生分组。
- 渲染器测试覆盖圆点/箭头切换、活动后代提示、ARIA 属性和缩进 CSS 变量。
- 会话存储测试覆盖快速连续重设父关系、折叠状态、窗口隔离和标签 ID 替换。
- 浏览器视觉检查覆盖 180、240、300、360px 宽度以及浅色、深色和强制颜色模式。
