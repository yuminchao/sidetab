# 父子标签树设计

## 目标

在设置中新增“新标签打开方式”，允许用户选择“作为根标签”或“作为当前标签的子标签”。树模式开启后，侧边栏按真实打开来源展示多级标签树，同时保持现有原生标签组、批量操作和性能边界。

## Answer

### 关系来源

- 默认模式为“作为根标签”，长期保存在本地设置中；保存成功后才切换显示，取消或保存失败不改变当前状态。
- 树模式只采用 Chrome 明确提供的 `openerTabId`，以及侧边栏新增标签按钮显式设置的活动父标签，不把其他新标签推测为活动标签的子标签。
- 快捷网站、收藏夹、历史记录和复制标签打开的标签保持根标签；复制标签与来源标签保持同级语义。
- 开启树模式时立即根据当前 Chrome 标签快照构建已有关系；关闭时恢复 Chrome 原始平铺顺序，并清除树的浏览器会话状态。

### 层级与原生边界

- 支持真实多级标签树；每级缩进 12px，最多显示 4 级缩进，更深层仍保留真实关系。
- 固定标签始终作为根标签，不显示子树；父子任一方固定时暂时抑制关系，取消固定且关系仍有效时恢复。
- 父子关系只在双方均未分组或处于同一 Chrome 原生标签组时展示，不跨越分组边界；边界恢复一致时可恢复关系。
- 无效父标签、自引用和循环关系在本轮渲染中降级为根标签，不修改 Chrome 数据，也不阻塞其他标签。

### 排序与展示

- 父子结构的视觉表达参考 Confluence 侧边栏内容树：父项与后代形成连续分支，子项按层级逐级缩进，有后代的行在左侧提供展开/折叠箭头。
- 该参考仅约束层级识别、缩进和分支展开方式，不复制 Confluence 的品牌色、字体、行高、图标或完整拖放重挂交互；SideTab Lite 继续沿用现有紧凑标签行、favicon、活动标签高亮和原生分组视觉。
- 整棵标签子树紧跟父标签连续展示；兄弟标签按 Chrome `index` 排序，因此树模式下侧边栏顺序可以不同于 Chrome 顶部标签栏。
- 不显示树形连接线或子标签数量，只使用缩进和展开箭头。
- 有后代的父标签可折叠；折叠只隐藏后代，不关闭标签。活动标签的祖先路径自动展开并滚动到可见区域。
- 父标签已折叠时，后台新子标签保持隐藏；新子标签成为活动标签时才展开祖先路径。
- 原生标签组折叠与标签树折叠相互独立；重新展开原生分组后恢复内部子树状态。

### 交互与可访问性

- 展开箭头是独立按钮，只切换折叠，不激活父标签，并提供 `aria-expanded` 和明确标签。
- 父标签行支持 `ArrowRight` 展开、`ArrowLeft` 折叠；`Enter` 和空格保持激活标签。第一版不切换为严格 ARIA tree，仅增加 `aria-level` 等必要语义。
- 拖动父标签时整棵子树作为连续块移动，包括折叠隐藏的后代，并同步 Chrome 标签顺序。
- 子标签在同一父标签的直接子标签区域内移动时只调整兄弟顺序；放置到子树之外时解除关系并提升为根标签。第一版不支持拖到其他父标签下重新挂载。
- 从 Chrome 顶部标签栏移动子标签不解除关系；只有侧边栏中的明确拖出操作建立会话覆盖。
- 第一版不新增“关闭子标签”“关闭整棵子树”“展开全部”等树专用右键命令。

### 生命周期与批量操作

- 关闭父标签只关闭真实目标，其直接子标签提升为根标签并保留各自后代关系；所有现有关闭命令不隐式关闭整棵子树。
- “关闭上方/下方”“关闭其他同类网站”等命令继续按完整 Chrome 标签集合计算，包含折叠隐藏的后代。
- Chrome `onReplaced` 发生时，把原标签关系和折叠状态转移到替换标签。
- `onCreated` 信息不完整时立即使用已有信息显示，后续事件或完整快照到达后局部修正，不等待分组或 URL 信息阻塞首屏。

### 状态与性能

- 折叠状态和拖出解除覆盖写入 `chrome.storage.session`，只在当前浏览器会话有效；标签 ID 不进入长期本地关系存储。
- 使用以标签 ID 为键的映射，以 O(n) 构建关系并扁平化可见行；事件驱动局部更新，不反复扫描 DOM，不增加轮询、额外 Chrome 查询或后台常驻任务。
- 目标规模为 500 个标签，保持现有增量 DOM 协调和首屏渐进加载边界。

## 确认结果

用户已确认全部设计决策。本讨论已解决，可以此文档为输入编写正式规格和实施计划。
